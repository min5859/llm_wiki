## 인사이트·노하우

- **초기화권(리셋) 인식 불가 트러블슈팅** (P7): 초기화권을 사용했는데 오픈클로가 초기화된 것을 인식 못하고 계속 "한도 없음"으로 표시됨. 시도한 방법(재부팅 → 게이트웨이 재시작 → OAuth 재로그인 → `/new` → `doctor fix`) 모두 실패했으나, **`/reset` 명령으로 해결**됨.
- **Claude Code vs Codex CLI vs Grok Build vs OpenClaw vs Hermes 커스터마이징 범위 비교** (P18): "설정 수정", "에이전트 코어 수정", "AI 모델 자체 수정"은 서로 다른 층위라는 점을 강조.
  - Claude Code: 설정(`settings.json`, `CLAUDE.md`, 훅, MCP, 플러그인, 스킬, 서브에이전트, 시스템 프롬프트 교체)까지는 매우 자유롭지만 코어는 비공개(`All rights reserved`)라 포크 개조 불가. 더 깊은 커스텀은 Agent SDK로 별도 에이전트를 만드는 방식.
  - Codex CLI: CLI·SDK·App Server 소스가 Apache 2.0으로 공개되어 있어 실행 루프·도구 처리 등 코어까지 포크 개조 가능(단 Codex 클라우드/IDE 확장, 모델 서버는 비공개).
  - Grok Build: 2026년 7월부터 에이전트 루프·도구·TUI·플러그인/훅/MCP/서브에이전트까지 오픈소스화되어 OpenClaw/Hermes와 유사한 자유도를 갖게 됨(단 모델 가중치는 비공개).
  - OpenClaw/Hermes: 에이전트 코어까지 MIT로 수정 가능, 모델 자체 수정 여부는 연결한 모델에 따라 다름.
  - 결론: "완전히 통제하려면 오픈소스 에이전트 코어 + 로컬 오픈웨이트 모델 조합이 필요."
- **하네스별 역할 분담 워크플로** (P18): 오픈클로/헤르메스는 커스텀해서 쓰고 Claude Code/Codex는 순정으로 사용. 오픈클로·헤르메스가 막히는 작업은 Codex/Claude Code에 넘기고, 반대로 Codex/Claude Code가 막히면 오픈클로·헤르메스로 넘기는 상호 핸드오프 체제를 운용 중("서로를 인식하고 있고 핸드오프 잘 써줘서 딱히 불편함 못 느낌").
- **토큰 절약을 위한 모델 간 작업 분담** (P18): 클로드코드로 LLMWIKI·온톨로지 작업을 시키다가 토큰을 많이 태울 상황이면, 그록빌드에게 후속 가공을 맡기는 방식으로 비용을 분산.
- **claude -p vs Claude Code 성능 차이** (P12, P17): 동일한 클로드 모델이라도 `claude -p`로 쏘는 것과 Claude Code로 직접 쓰는 것 사이에 상당한 성능 차이가 있음. 이를 극복하려고 설정·프롬프트를 튜닝하지만 Claude Code 수준으로 끌어올리기는 어려움. Hermes에서 클로드코드 `-p`로 시키는 것보다 클로드코드에 직접 시키는 게 더 잘한다는 관측(원인은 모델 차이/하네스 차이로 추정, 불명).
- **ACP를 통한 직결 방식 제안** (P50): 위 성능 차이 문제에 대해 "ACP로 세션을 열어서 바인딩시켜달라고 하라"는 대안 제시. OpenClaw에서는 ACP로 Claude를 연결해 쓰고 있음(P51). Hermes에서는 아직 성공 못함(P51).
- **PPT/Excel OCR 자동화 실전 비교** (P17): PPT나 Excel을 OCR해서 문서를 보고 이름을 바꾸고 숫자값을 채우는 작업에 클로드코드가 가장 잘함. 클로드코드에게 헤르메스를 통해 컴퓨터 사용(Computer Use)류 권한을 쓰라고 시켜도 잘 처리함 → "클로드 코드를 메인으로, 헤르메스는 다른 에이전트 창구로" 쓰는 방향으로 전환 검토 중.
- **회사 업무 자동화 사례** (P7): 회사 엑셀 시트에 사람이 직접 회사 사이트에서 데이터를 복사·붙여넣기 해야 했던 작업을, 구글 스프레드시트 + 크롬 익스텐션으로 구현해 "조회" 버튼 클릭 시 자동 로딩되도록 개선. 최종적으로 엑셀/PDF로 내보내는 기능까지 구현. 오픈클로가 크롤링과 데이터 입력을 잘 처리해줌. 과거 JavaScript로 크롤링·크롬 익스텐션을 만들어본 경험이 도움이 되었다고 언급.
- **코덱스 사용량 급증 이슈** (P7, P18, P9): 코덱스 주간 사용량이 짧은 시간에 60~66%(P7), 20%(P18)까지 급증. P9은 동일 현상 없었다고 함. P18은 "사용량 버그인가 싶기도 하다"고 추정(불명, 원인 미확정).

## 자동화·시스템 적용 후보

- **구글 스프레드시트 + 크롬 익스텐션 기반 업무 자동화** (P7): 사람이 수작업으로 회사 사이트에서 복사·붙여넣기 하던 데이터를 "조회" 버튼 클릭 한 번으로 자동 로딩하고, 결과를 엑셀/PDF로 내보내는 구조. 오픈클로가 크롤링·데이터 입력 부분을 담당. 비슷한 매월 시장단가 크롤링→견적 반영 스프레드시트 사례가 P44에게도 있음(다만 개발에 2달치 Pro 사용량을 소모했다고 함).
- **URL 감시용 크론잡 패턴** (P18): 특정 상품 페이지(카카오 선물하기) URL을 주기적으로 크롤링해 재출시 여부를 감시하는 크론잡을 즉시 구축한 사례. "혹시 모르니 클론으로 감시체계 구현"이라는 제안이 실제 실행으로 이어짐.
- **모델 간 역할 분리 워크플로**: (1) 오픈클로/헤르메스(커스텀) ↔ Claude Code/Codex(순정) 간 상호 핸드오프 체제, (2) 클로드코드가 메인 작업, 그록빌드가 토큰 절약용 후처리 담당, (3) 클로드코드를 메인 에이전트로 헤르메스를 보조 창구로 쓰는 재편 검토 — 모두 "막히는 작업을 다른 하네스에 넘기는" 공통 패턴으로 다른 시스템에도 적용 가능.
