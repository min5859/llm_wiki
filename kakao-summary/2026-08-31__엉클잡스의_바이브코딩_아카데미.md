# AI 요약

## 인사이트·노하우

- **에이전트 경쟁 축이 모델 → 스킬로 이동**  
  “어떤 모델을 쓰느냐”보다 “언제든 갈아탈 수 있느냐”, “어떤 스킬을 꽂아 무엇을 시키느냐”가 더 중요해지는 흐름으로 정리됨.

- **OpenAI ↔ Cursor 모델 공급 종료(뉴스)**  
  - 배경: SpaceX가 Cursor(Anysphere) 인수 이후 OpenAI가 모델 공급 계약 종료 발표  
  - 제안 종료일: **2026년 11월 12일**  
  - 시사점: 모델 벤더 lock-in을 피하고 전환 가능성을 갖추는 것이 중요

- **개인용 vs 팀용 에이전트 도구 역할 분리(실사용자 결론)**  
  - **그록봇**: 개인 업무용  
  - **버즈(Buzz)**: “사람 + 에이전트 OS” — 팀 구축·사내 시스템용  
  - VPS(Hostinger) 입문 배경: 버즈 때문에 시작, 외주업체 사내 인트라넷·메신저 테스트 + “강제 에이전트 컨설팅” 아이디어 검증 목적

- **버즈 커뮤니티 초대의 제약과 우회(병원 PC 사례)**  
  - 원인: 커뮤니티 초대하려면 **개인 버즈 계정 + 각자 컴퓨터**가 필요  
  - 시도/해결(우회): 병원 컴퓨터에 잠시 설치 → **토큰 키 발급** → 모바일 연동·초대 → **병원 PC에서 버즈 삭제**  
  - 평: “아직은 불편”, 사내 시스템엔 괜찮지만 고객사 소통엔 어려울 수 있음  
  - 개선 희망: **모바일만으로 가입 가능**하면 훨씬 좋음 (“에이전트 만들어서 파견” 용이)

- **바이브코딩에서 설계를 그림으로 남기는 이유(archify 맥락)**  
  말로만 설명한 설계를 **그림 → 문서 → 에이전트 컨텍스트**로 남기면, 다음 에이전트에게 넘길 때 **컨텍스트 손실이 크게 줄어듦**

- **omo 데스크톱 출시 여부**  
  채팅 답변: **아직 공식 데스크톱 출시 아님** (P11: “데탑은 아직입니다”). P12의 “유출” 언급은 맥락 불명.

## 추천·자료

브리핑에서 “오늘 해볼 것”으로 **실전성 높다**고 직접 꼽은 2개:

- **archify** — 워크플로·시퀀스·데이터 플로·시스템 라이프사이클 입력 → 실행 가능한 HTML 다이어그램 생성. 서비스 구조를 넣고 시퀀스/데이터 플로/시스템 구조 중 하나만 뽑아보는 실험 권장.
- **last30days-skill** — Reddit·X·YouTube·HN·Polymarket·웹에서 **최근 30일**만 근거와 함께 정리. 관심 키워드 하나 넣고 “최근 30일만 조사해줘”로 돌려보면 뉴스·시장조사·콘텐츠 소재 수집에 바로 연결 가능.

기타 공유 레포(맥락 한 줄):

- **OpenMAIC** — 여러 AI 에이전트가 역할 분담해 가르치는 오픈 멀티에이전트 교육 플랫폼. 에이전트가 코딩을 넘어 교육·튜터링으로 확장되는 흐름 예시.
- **scientific-agent-skills** — 생물·화학·의학·신약 연구용 스킬·DB 묶음. Cursor·Claude Code·Codex 등에 붙여 **코딩 → 리서치 → 전문 도메인** 확장 사례.
- **crawl4ai** — 웹페이지를 LLM/에이전트가 쓰기 좋은 형태로 정리. RAG·리서치 에이전트의 **웹 → 깨끗한 컨텍스트** 기본 인프라.
- **freellmapi** — 여러 무료 LLM 제공자를 OpenAI 호환 API + 라우팅 + 장애전환으로 묶음. **개인 실험용** 명시 — 상용 투입은 별도 검증 필요.
- **livekit/agents** — 실시간 음성 AI 에이전트 프레임워크. 전화·음성비서·상담 등 실시간 인터랙션 방향.
- **GitNexus** — GitHub 레포/ZIP을 브라우저에서 Knowledge Graph + 그래프 기반 질의 에이전트로 분석(서버 없이 클라이언트). 낯선 대형 코드베이스를 **파일 목록이 아닌 관계도**로 이해할 때 유용.
