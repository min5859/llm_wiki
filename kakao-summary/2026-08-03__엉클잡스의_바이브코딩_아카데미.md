## 인사이트·노하우

**Terax(Rust/Tauri 개발 워크스페이스) macOS 한글 IME 입력 버그 — 원인 분석 및 해결 시도**
- 증상: macOS에서 Terax 설치 후 터미널 영역에 한글 입력이 안 됨 (P20)
- 원인 분석 (P20 공유):
  - xterm.js 렌더러에 IME 인식 코드는 존재 (`rendererPool.ts` 250~258번 줄: `if (event.isComposing || event.keyCode === 229) return false;`)
  - 그럼에도 실패하는 이유: ① xterm.js + WebGL 렌더러 + Tauri/WKWebView 조합이 IME에 취약해 조합 UI(밑줄 텍스트, 후보 팝업)가 캔버스 렌더러에서 깨짐 ② `compositionstart/update/end` 이벤트를 명시적으로 처리하지 않음 ③ WKWebView의 포커스 관련 엣지케이스 가능성
  - 진단 팁: 하단 명령 입력바(CodeMirror 6 기반)에서는 한글이 되는지 먼저 확인하면, 터미널 영역(xterm.js)만의 문제인지 구분 가능
- 해결/우회 방법: ① GitHub([crynta/terax-ai](https://github.com/crynta/terax-ai/issues))에 OS 버전·앱 버전(0.8.6)·재현 방법 명시해 이슈 등록 ② 임시방편: 다른 앱(TextEdit, 브라우저)에서 한글 입력 후 복붙
- 후속 조언: 이슈 등록 후 직접 PR을 올려 머지시키면 좋은 경험이 된다는 조언(P2: "머지되었을 때 쾌감이 있어요")

분석 결과

잘 구현된 부분: Terax는 xterm.js 터미널 핸들러에 IME 인식 코드가 있습니다 (rendererPool.ts 250-258번 줄):
if (event.isComposing || event.keyCode === 229) return false;
이 코드는 IME 조합 중에 키 이벤트가 PTY로 전송되는 것을 올바르게 방지합니다.

문제점: 이 코드에도 불구하고, 한글 입력이 실패하는 이유:
1. xterm.js + WebGL 렌더러 + Tauri/WKWebView 조합이 IME에 취약합니다. 조합 UI(밑줄 표시된 텍스트, 후보 팝업)가 커서 위치에 정확히 렌더링되어야 하는데, 캔버스 기반 렌더러에서는 종종 깨집니다.
2. 명시적인 IME/조합 이벤트 핸들러 부재 — 코드베이스에 키 이벤트 가드만 있고, xterm.js가 조합 텍스트 표시에 의존하는 compositionstart, compositionupdate, compositionend 이벤트를 명시적으로 처리하지 않습니다.
3. Tauri의 WKWebView는 macOS에서 특정 포커스 상황에서 IME 입력과 관련된 엣지 케이스가 있을 수 있습니다.

해결 방법

1. 버그 리포트: <https://github.com/crynta/terax-ai/issues> 에 다음 내용으로 이슈를 올려주세요:
  - macOS 버전
  - Terax 버전 (0.8.6)
  - 재현 방법: "한글 입력으로 전환 후 터미널에서 입력하면 자음이 모음과 조합되지 않음"
2. 임시 해결책: 다른 앱(TextEdit, 브라우저, 메모장)에서 한글을 입력한 후 Terax로 복사-붙여넣기하세요.
3. 테스트: 명령 입력바(하단의 ❯ 입력창)에서는 한글이 작동하는지 확인해보세요 — dort에서 사용하는 CodeMirror 6는 IME를 더 잘 처리할 것입니다. 거기서 되고 터미널 영역만 안 되면 xterm.js 관련 문제가 확실합니다.
