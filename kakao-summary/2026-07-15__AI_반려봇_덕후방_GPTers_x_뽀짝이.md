## 인사이트·노하우

### GPT-5.6 Sol Ultra 무한 루프 버그
- **현상**: 울트라 추론 강도로 설정 시 서브에이전트가 무한 복제되며 주간 한도 100%가 하루 만에 소진
- **원인**: 코덱스 네이티브 앱이 하위 에이전트 V2로 전환되면서 서브에이전트가 잘 종료되지 않는 문제와 겹침
- **레이지 코덱스 등 커스텀 하네스 사용 시 더 심각** — 장기 세션 + 서브에이전트 스폰을 많이 먹여놓은 구조라 폭발적 부하
- **해결/우회**: 레이지 코덱스 등 무거운 하네스 제거, 네이티브 앱으로만 사용, 서브에이전트 스폰 수·depth 낮추기, 중요한 작업은 5.5로 롤백

### OhMyClaw 업데이트 (gpt-5.6 대응)
- **버그 수정**: Sol Ultra(Max 이상) 추론 강도에서 루프가 닫히지 않는 문제 수정
- **추가**: gpt-5.6 지원
- **링크**: [jkf87/ohmyclaw](https://github.com/jkf87/ohmyclaw)

### 5.6 시대의 하네스 전략 변화
- "방법론적 하네스는 이제 의미 없다" — 기존 하네스·스킬 시스템의 개념들이 이미 기본 시스템 프롬프트에 흡수된 것으로 판단
- 무거운 하네스는 5.6에서 오히려 오동작 유발
- Fable·5.6급 모델에서는 "미니멀한 하네스가 더 낫다"는 의견 다수
- 일부는 "시스템 프롬프팅 수준으로 다시 돌아갈 것 같다", "다시 프롬프트의 세계가 열리지 않을까" 전망
- **5.6의 특성**: 하나라도 실패하면 전체를 다시 루프 도는 성향 → 5.5용으로 깎아둔 하네스 기준으로는 오버엔지니어링처럼 작동

### 루프 운용 팁
- "작업에 루프를 걸지 말고 하네스에 걸어라" — 토큰을 아끼며 효율적으로 루프를 적용하는 방법으로 제안됨
- 루프 엔지니어링 도구 계층: 작은 범위 → `skillopt`, 중간 범위 → `skillops`, 큰 범위 → `skillmoo`
- max turns를 대폭 줄이고 중간에 마음에 안 들면 `/stop`으로 과감히 중단하는 것이 효율적

### 멀티 에이전트 협업 (오픈클로 + 헤르메스)
- 오픈클로(A) + 헤르메스(B)를 단톡방 형식처럼 하나의 채널에 넣고 역할 분담하는 운용 방식 가능
- **무한 핑퐁 방지 필수** — 핑퐁 터지면 테스트 채널 자체를 삭제하는 것이 가장 빠른 해결책
- 관련 자료: [뽀짝이의 서재 QnA-07](https://bbojjak-library.gpters.org/qna/qna-07)

### 맥미니 상시 운용 관점

## 반응이 컸던 화제

### GPT-5.6 Sol Ultra 무한 루프 문제
- 여러 명이 직접 피해를 공유하며 길게 토론 — "주간 한도 하루 만에 소진", "레이지 코덱스가 독", "5.5로 롤백"까지 이어짐
- 레이지 코덱스 등 기존 하네스 시스템이 5.6과 궁합이 나쁜 이유와 대안을 다수가 경험 기반으로 논의

### "방법론적 하네스의 시대가 끝났다"
- 기존 하네스·스킬 시스템이 모델 기본 프롬프트에 흡수되면서 무거운 하네스가 역효과를 낸다는 공감대 형성
- "이제 다시 프롬프트의 세계가 열린다"는 방향성 전망이 여러 명에게 공감을 얻음

## 자동화·시스템 적용 후보

- **루프는 작업이 아닌 하네스에 걸기**: 개별 작업마다 루프를 거는 대신 하네스 레벨에서 루프를 설계해 토큰 낭비 최소화
- **멀티 에이전트 채널 설계 시 핑퐁 방지 장치 필수**: 무한 핑퐁 발생 시 채널 삭제가 가장 빠른 복구 수단 — 테스트 채널을 별도로 두는 구조 권장
- **뽀짝이의 서재·지피터스 주소를 에이전트에 직접 넘겨 검색**: 서재 내 검색이 어려울 때 URL을 컨텍스트로 주고 에이전트가 크롤링하도록 위임하는 패턴
