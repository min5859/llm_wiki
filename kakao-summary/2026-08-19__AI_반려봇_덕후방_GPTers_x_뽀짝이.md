# 카카오톡 대화 정리 — GPTers x 빼빼기 (2026-08-19)

## 인사이트·노하우

### 에이전트 엔지니어링 본질
- 하네스(harness), 루프(loop), 그래프 엔지니어링은 표현은 달라도 **"시스템은 진화하지만 본질은 하나"** — AI를 더 잘 쓰는 방향으로 수렴한다는 관점.

### 멀티봇 판단기준 통일 (실무 난제)
- 여러 소스를 **하나의 판단기준으로 맞추는 작업**이 매우 어렵다는 공감.
- 제안된 구조: 한 봇이 기준에 맞게 정리 → 나머지 봇에게 넘기는 **허브-스포크 구조**.

### Stripe × OpenRouter 인수 (맥락)
- 블룸버그 보도: Stripe가 OpenRouter를 **70억 달러 이상**에 인수 마무리 (이틀 전 뉴스, 당시 공식 발표 전).
- Stripe: 글로벌 PG. OpenRouter: API 토큰을 판매하는 **백화점식 LLM 라우터** — 자사 토큰으로 여러 모델 사용.
- 해석: API 토큰이 **주요 재화**로 취급되기 시작. Stripe 에이전트 지갑과 합칠 가능성도 언급.
- Stripe는 PG 중 **가장 먼저 MCP 제공**했던 회사로 기억됨. 토큰 플랫폼 지향.

### Stripe vs 국내 PG (이니시스) — 실무 판단
- **국내 원화 결제가 필요 없는 글로벌 웹서비스** → "아묻따 Stripe"가 개발 친화적.
- Stripe 초기 전략: **"한번 잡솨봐"** — API를 일부 오픈하고 플랫폼에 붙여보라 → 매출 발생 후 계약. PG 업계에서 파격적이었음.
- 국내는 결제 표준이 고정되어 있어 글로벌 PG 붙이기 불편. 아고다도 원화 결제는 이니시스 사용.
- 이니시스 = **"결제계의 HWP"** — 원래 UI를 반드시 자사 윈도우 써야 했으나 글로벌 플랫폼 요구로 양보.
- Stripe로 국내 카드: 마스터/비자 연결 국내카드는 가능하나, **국내 사이트에서 Stripe 결제 UI를 본 적은 없다**는 경험담. BC카드 등이 "찐 국내카드".
- PG 붙이기는 지금은 일이 아닌 시대 — 예전엔 서류·연동이 매우 번거로웠음.

### Codex vs Claude — 작업 유형별 강점 (실측 경험)
| 영역 | 더 나은 쪽 | 근거 |
|------|-----------|------|
| HW(FPGA/ASIC/Verilog) | **Codex** | Vivado·TCL 굴리고 검증까지. 수십 시간 걸려도 꾸역꾸역 완수 |
| 수학·공학 | **Codex** | — |
| 문서·사무직 업무 | **Claude** | — |
| HMI 작화 (반례) | 둘 다 비효율 | 3일간 토큰 소모, 버튼 몇 개가 전부 |

- HW 개발 팁: **초장기 세션** + 기록·교훈을 남기게 하면 도움.
- RF SoC 사례: 6개월 해매던 것을 Codex로 3~4개월 시행착오 후 목표치 달성. 남은 일은 성능 검증 + AI 결과를 이해하고 매니저에게 설명.
- 실제 **tape out까지** Codex/Claude Code로 작업하는 경우가 흔해졌다는 관찰.
- 아키텍처만 설계해주면 Vivado 돌리고 TCL 검증까지 자동. ARM core 프로그래밍도 "알잘딱".
- 회로도: AI로 그리고 검수만. 아트웍(SI/PI): 퀄리티 검수가 번거로워 **간단한 것 아니면 외주**가 마음 편함. KiCad 지원은 하지만 검수 필요.

### Aside (AI 브라우저) — 핵심 노하우
- **가장 큰 가치**: "로그인된 세션에서 브라우저 자동화를 빠릿하게" — 기존 RPA(UiPath 등) 대비 압도적 속도감.
- **굳이 브라우즈 컨트롤(Playwright 등) 안 써도 됨** — 그냥 브라우저로만 써도 충분. 디폴트 브라우저로 설정하는 사용자도 있음.
- 크롬 툴킷·로그인 정보 이전 → 막히던 작업 편해짐. 캡챠도 잘 풀림.
- GPT·Claude·Grok **로그인 연결** 지원 (API 키 없이). Claude OAuth 연결 가능.
- **멀티 프로필**: 시큐어 레벨 지정 프로필 생성. 빈 프로필(로그인 정보 없음)로 시크릿 모드(Incognito) 테스트 가능.
- 에이전트 기능: 메모리가 **텍소노미 구조**. soul 등 고급 기능 있으나 docs에 미반영.
- MCP CLI로도 기존 에이전트에서 사용 가능.
- 유료($20): 텔레그램·슬랙·디스코드 연결 + 토큰 제공.
- 피드백내면 **거의 매일 바로 답장**. 업데이트·적용 속도 빠름. 한글 최적화.
- 단점: 브라우저 기반이라 속도가 LLM 직접 사용보다 느린 감. 윈도우는 아직 미지원(8월 중 예정). 코멧(퍼플렉시티 브라우저) 대비 "왜 이걸 쓰나" 포인트가 거의 해결됨.
- 실사용 예시:
  - AWS 콘솔 로그인 → "돈 나가는 서버 정리해줘" → 응답
  - 식봄 발주: 가격변동·쿠폰·최소배송비 자동비교 → 장바구니 → 가격변동 추적
  - 쿠팡 vs 직구 비교 (배송·세금 포함)
  - 네이버스토어 주문 (네이버가 막기 어려운 사이트)
  - 업비트 크롤링·매매, 쇼핑몰 포토리뷰 작성 등

### FPGA 취미·입문 판단
- 일반인 취미나 간단한 자동화 → **라즈베리파이 등 AP가 훨씬 나음**. FPGA는 "덕중의 덕".
- FPGA가 유리한 경우: **저지연, IO 통합, 고속 신호처리, 로직이 자주 바뀌는 경우**.
- KRIA: AP+FPGA 둘 다 가능. AP로 시작 → FPGA 필요 시 전환.
- Altera(인텔) 보드 10년 묵혀둔 것은 팔기도 어렵고, AMD Zed Board 등이 더 나을 수 있음.
- Xilinx/Zynq MPSoC 개발보드는 칩이 비싸서(수백만~수천만 원) **대기업 수준** 신규 HW 개발에 적합. 삼성 MIPI 센서 붙일 때 보드 몇 장씩 날리는 건 부지기수.
