## 인사이트·노하우

- **카카오톡 챗봇 아키텍처 (P12 실전 사례)**: macOS `launchd`(크론)로 1분 주기마다 특정 방의 전체 대화를 CSV로 내보내기 → 1분 전 스냅샷과 비교해 새로 추가된 메시지 탐지 → 그 안에서 봇 이름 호출 여부 확인 → 호출됐으면 `claude -p`로 답변 생성 후 해당 톡방에 전송하는 구조. "호출한게 있으면 답하라고 해놓았는데 실제로는 큐방식처럼 하나씩 처리되더라고요"라는 언급대로, 의도치 않게 큐(queue) 방식처럼 순차 처리되는 특성이 있음. 카톡 로컬 DB에 직접 접근하는 `kakaocli` 류 방식과 달리, 사람처럼 카톡 앱에서 지정한 방을 직접 열어 작업을 수행하는 방식이라 동시에 여러 명/여러 방을 관리하지는 못함.
- **카카오톡 챗봇 밴(계정 정지) 위험**:
  - LOCO 방식(카카오 프로토콜 직접 접근) 봇은 계정 밴 위험이 있다는 이야기가 있음(P12, 본인 미경험이라 "잘 모르겠습니다"로 불확실).
  - 챗봇이 운영 중인 방에 "자주 들락날락"하면 밴 대상이 됨 — P20 실제 밴 경험 있음.
  - 단순히 대화를 읽기만 하는 것은 상대적으로 안전하지만, 봇이 답장(응답)을 하기 시작하면 밴 위험이 크게 올라간다는 의견(P38): "읽는 건 잘 안 걸리는 것 같아요 / 근데 이제 답변을 해야한다 / 이러면 좀 많이 위험해집니다".
  - 실제로 이 방에서 활동하던 "홀든" 계정이 카카오로부터 영구밴 당한 사례가 있었음(P12).
