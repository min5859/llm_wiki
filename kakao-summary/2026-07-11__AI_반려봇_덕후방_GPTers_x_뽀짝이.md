# AI 요약

## 인사이트·노하우

### AI 코딩에서 디자인 품질 높이기

- **디자인 시스템 구축이 핵심**: 클로드코드에 디자인을 바로 맡기면 품질이 낮게 나온다. 레이아웃·CSS를 잡는 디자인 시스템을 먼저 구축해야 함.
- **해외 디자인 시스템 참고 권장**: 한국 디자인 시스템보다 해외 사례를 참고하는 편이 결과물 퀄리티가 높음.
- **이미지 생성과 레이아웃은 별개 문제**: 웹사이트 디자인 개선은 이미지 생성이 아니라 CSS/레이아웃이 먼저. 두 단계로 분리 필요: ① 레이아웃 잡기 → ② 이미지 생성.
- **레퍼런스 사이트 활용**: "기대하는 완성본을 모르는데 마음에 들 때까지 계속 돌려보면서 모델탓 할 수는 없다" — 원하는 레이아웃의 레퍼런스를 찾아 똑같이 구현 지시.
- **HTML → PPT 변환 패턴**: HTML로 디자인 틀을 먼저 잡게 한 뒤 PPT로 변환하면 품질이 나아짐. Codex 앱/CLI 모두 PPT 생성 잘 됨.
- **OKLCH 색상 세팅**: 헥스코드 대신 `oklch`로 색을 세팅하면 더 정확함 — 디자인 시스템 색 설정 시 적용 권장.
- **디자인 시스템 계층화 패턴**: 공통 엔진 + 개별 테마 두 계층으로 분리하면 AI가 디자인 시스템을 더 잘 이해하고 일관된 퀄리티 출력.

### 스킬/에이전트 아키텍처 (P5 실무 경험)

- **스킬 연쇄 트리거 구조**: 스킬에 스킬을 엮어 연쇄 트리거되도록 구성 — 하네스 계열 아님, 코드게이트는 최소화.
- **코드게이트 + 리페어 루프**: 상시트리거 에이전트에 코드게이트를 통과해야만 답변하게 하고, 미달 시 리페어 루프를 돌게 설계. 단 초기 라우팅(단순 호명·채팅)은 즉시 답변.
- **미감+QA 트리 vs 생성 워크플로우**: "디자인시스템디렉터(미감+QA)" 와 "스튜디오 스킬트리(생성 워크플로우)"를 분리 운용 중.
- **5.6부터 장시간 작업 가능**: GPT 5.6부터 80분까지 연속 작업 가능 확인. `maxTurns` 으로 조정.

### 모델별 디자인 성능 비교 (커뮤니티 실사용)

| 모델 | 특징 |
|---|---|
| GLM 5.2 | 디자인 분야 SOTA 평가. OpenRouter에서 소량 충전 후 사용 권장 |
| GPT 5.6 sol xhigh | 현재 주력 (P5). 솔 엑하가 가장 좋다는 공통 의견 |
| Fable (페이블) | 전자책 등 콘텐츠 생성 효율 최고. 소넷보다 토큰 소모 적음 |
| Sonnet | 토큰 소모 가장 큼 |
| Grok 4.5 high | MoA 방식으로 간헐적 활용 |

- **"모델이 좋아야 오히려 절약된다"** — 저품질 모델로 반복 시도하는 것보다 고성능 모델 한 번이 경제적.

## 자동화·시스템 적용 후보

- **디자인 시스템 2계층 패턴**: `공통 엔진(색상 토큰·타이포·레이아웃 그리드)` + `개별 테마` 분리 → AI에게 테마 파일만 참조시키면 일관성 유지. 신규 프로젝트 스캐폴딩에 도입 가치 있음.
- **HTML → PPT 자동 변환 워크플로**: HTML 시안 생성 → PPT 스킬로 변환하는 2단계 파이프라인. Codex CLI에서도 동작 확인됨.
- **스킬 연쇄 트리거 + 코드게이트 리페어 루프**: 에이전트 응답 품질이 기준 미달일 때 자동 리페어 루프를 돌고, 기준 통과 시에만 최종 응답 출력하는 구조 — 상시 트리거 에이전트에 적용 가능.
