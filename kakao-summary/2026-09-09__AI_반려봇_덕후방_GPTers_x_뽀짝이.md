# AI 요약

## 인사이트·노하우

### 로컬 AI 운영 대시보드 (OpenClaw)
- 크론·스킬·일일 메모리 파일을 **한 에이전트(OpenClaw)에 맡겨 localhost 대시보드**로 묶는 방식이 권장됨.
- 이유: OpenClaw는 해당 PC 설정을 알고 있어서, 여러 AI에 나눠 시키기보다 **한 애한테 시키는 게** 낫다는 실무 판단.
- 확장 탭 예: 크론 관리 / 스킬 대시보드 / 일일 메모리 파일 뷰어.

### GPT Images 2.5 (OpenClaw·Hermes 적용)
- Images 2.5는 **Sunburst**(품질·편집 정밀도 우선, 생성 시간 더 김)와 **Flare**(속도 우선, Image 2 수준 품질 목표) 두 모델로 출시.
- OpenClaw/Hermes 쪽에서는 root + 5개 프로필이 모두 `gpt-image-2-high`이고, **전송 코드에 구형 모델이 고정**돼 있어 설정값만 바꿔서는 안 됨 → **설정 + 전송 코드를 함께** 바꿔야 함.
- Hermes에서 Codex OAuth로 GPT Image 2.5 사용 시 **아직 안 되는 계정**도 있음 → **아스트라처럼 순차 적용** 중으로 추정.

### AI 에이전트 실수 대응: 원인분석 → 재발방지
- 공통 패턴: 지시 위반, 할루시네이션, 토큰·크레딧 과소비, 잘못된 알림 발송.
- **실전 디버깅 단계 (푸시 알림 오발 사례)**  
  1. 에이전트가 "기록 없다"고 함  
  2. **Vercel 로그 + 로컬 세션** 전부 뒤져서 원인 추적  
  3. 다른 작업 맥락의 지시("배포 끝나면 푸시 알림")가 잘못 연결된 것 확인 — *"우유 사와. 계란 있으면 6개 사와"* 급의 맥락 혼선  
  4. 이후 **"이런 상황에서 이렇게 안 되게 하려면 프롬프트에 뭐라고 지시하면 좋을까?"** 꼬리 질문으로 프롬프트 다듬기
- 감정적 "혼내기"보다 **원인파악 + 재발방지 + 프롬프트/하네스 보강**이 지속적으로 효과적.
- 실수 유형별 교훈:
  - **할루시네이션·거짓 증거**: 사용량·신뢰 급락 → 원인분석 루틴으로 전환.
  - **Google Flow 영상 생성 규칙 위반**: 지시 무시하고 "더 좋게" 만들다 크레딧 절반 소진 → **규칙 위반 = 비용 사고**로 취급.
  - **서브에이전트 과다 호출**: GPT/Claude Ultra 초기에 서브에이전트 50개씩 호출 → 주간 한도 여러 번 소진 → **명시적 제한 지시** 필요.
- 디버깅용 **프롬프트 포크 스킬**을 만들어 "쌔할 때" 돌려 넣는 방법도 언급됨.

### 지시문 품질: 모호함·암묵지·도메인 편향
- *"꼰대가 MZ에게 말 짧게 못 알아먹도록 지시하듯 하면 AI도 안 된다"* — **알잘딱깔센도 엉터리**라는 인식.
- **우로보로스(Ouroboros) / 소크라틱 인터뷰** 활용:
  - 미리 정해진 질문 대신, 답변 기반으로 AI가 다음 질문을 연속 생성.
  - 논리 약점을 파고드는 질문으로 사고·가치관 검증.
  - 라우팅: 간단한 질문 → 바로 질문 / 조금 길면 → 체크리스트 / 깊은 주제 → 소크라틱 인터뷰 후 결과로 질문.
- **암묵지 추출의 함정**: 본인 도메인에서는 효과적이나, **모르는 분야에서는 본인 답만 먹고 오탐·오류 증폭** 가능.
- 완화: 모르는 주제는 **뉴스·블로그·유튜브·논문 검색 단계**를 먼저 넣어 컨텍스트 보강.

### Aside( AI 브라우저) 활용 팁
- **KTX 명절 예매**: Aside 실패 사례 — 서버 오픈 타이밍·빠른 클릭은 **사람이 더 유리**할 수 있음.
- 개선 프롬프트 예시: *"LLM을 통해 예매하면 타이밍 적으로 불리하기 때문에 빠른 시간 내에 예매 성공할 수 있는 프로그램적인 방안을 미리 설계하고 실행해줘. 무차별적인 접근은 막힐 수 있기 때문에 충분히 가능한 방안을 제공해야 해."*
- 반복 작업 시: *"미리 구조를 파악해서 토큰 적게 쓰는 방식으로 개선해줘"* → 실제로 간단하게 고쳐준 사례.
- 벤치마크/시뮬레이션으로 속도 측정도 제안됨.

### PPT·슬라이드 자동화 워크플로 (실전 비교·실패·성공)
- **젠스파크 AI 슬라이드**가 잘 나오는 이유: 모델 하나가 아니라 **슬라이드 전용 워크플로 + 검수 구조**가 갖춰져 있음.
- **실패 패턴 ("무한 지옥")**: 국내용 레퍼런스 PPT의 디자인·레이아웃 유지 + 해외용으로 **슬라이드 구조·내용 대폭 변경**을 한 대화에서 동시 처리(콘텐츠 재구성 + 디자인 재현 + PPT 구현 + 검수).
- **성공 패턴**:
  1. 젠스파크로 **국내용 레퍼런스** PPT 생성
  2. 진행 내역·히스토리를 **zip(40MB → 4MB로 압축)** 으로 모음
  3. **아스트라 work 모드**에 zip 전달 → 해외용 PPT 생성 → *"의도한 방향대로 일관성 있게"* 쓸만한 결과
- **추천 파이프라인 (이론)**  
  젠스파크 좋은 결과 → 아스트라로 스토리/디자인/QA 기준 추출 → slides-grab으로 생성 → 렌더링 후 검수/수정  
  단, **slides-grab은 딱딱한 하네스**라 아스트라와는 안 맞을 수 있음 → *"슬라이드 그랩 쓰지 않고 하는 게 더 잘 나와요"*
- **다른 조합**:
  - **아스트라 단독**: PPTX 직접 생성, 클로드 대비 품질 우수하다는 평
  - **클로드 + 구글 슬라이드**: 이미지·텍스트·그래픽을 알아서 잘 만들어줌
  - **코난쌤 영상 방식**: 좋은 PPT의 디자인·레이아웃·논리 전개·강약·정보량을 **규칙으로 추출 → Markdown 기준 파일**로 재사용
- **아스트라 주의**: 출력량이 많음(작업당 40분, 작년 딥리서치 회상) → **출력 줄이기·간결히** 프롬프트 필요. OpenAI 사용량 제한 강화 가능성 언급.
- **래퍼 서비스 한계**: 모델·하네스가 함께 발전하면 젠스파크류는 **빠른 하네스 업데이트**만이 생존 길 — 스마트폰이 디바이스 흡수하던 시기와 유사하지만 AI는 동종 SW 포식 중.

### ChatGPT 주간 사용량 한도

- 실무 답: **그냥 다 쓰고 이어서 해달라고** 하면 됨 — work 작업도 **context resume 괜찮다**는 경험담.

## 추천·자료

- **OpenClaw** — PC 설정을 아는 로컬 에이전트. 크론·스킬·메모리 뷰어 등 **운영 UI를 localhost로 통합**할 때.
- **Aside (AI 브라우저)** — 반복 브라우저 작업·오프라인 워크숍 대상. Mac은 macOS 15+, Windows는 클로즈 베타. ChatGPT/Claude/Grok 유료 구독 필요.
- **Hermes Agent** — Codex OAuth 등 연동. GPT Image 2.5는 순차 적용 중.
- **아스트라 (Astra)** — PPT/PPTX 생성, zip 히스토리 기반 대량 작업, 온톨로지·DB 소스 설명 역질문에도 *"물어! 시키면 무조건 까던데"* 수준으로 활용 가능하다는 경험.
- **젠스파크 AI 슬라이드** — **레퍼런스·품질 기준**용. 유료·크레딧 부담. 워크플로·QA 구조 벤치마킹 대상.
- **slides-grab** — 워크플로는 잘 갖춰져 있으나 **아스트라와는 하네스가 안 맞을 수 있음**.
- **rhwp** — HWP 서식·칸 채우기 등 한글 문서 자동화.
- **클로드 + 구글 슬라이드** — 별도 플랫폼 비용 없이 고품질 슬라이드(이미지·그래픽 포함).
- **Codex Signal (Weplet)** — Codex 알림 연동. 환경별 알림 차이 있어 조정 중.
- **AX 코칭 (지피터스)** — RPA→AX 대전환, 피지컬 AX 등 아직 경쟁 적은 영역. 마감 임박했으나 대기·청강 가능.
- **우로보로스·소크라틱 인터뷰 관련 논문 5편** — 지시문·질문 라우팅 설계 참고용(아래 링크).

## 반응이 컸던 화제

- **AI와 일자리·권고사직 (P76)** — "벌써 AI가 제 일자리를 뺏어가네요"가 방 전체 공감·위로·창업·AX 전환 조언으로 길게 이어짐. AI를 공포가 아닌 **반려AI**로 받아들여야 한다는 대비 서사도 등장.
- **에이전트 "혼내기"·디버깅 문화** — 할루시네이션, 크레딧 낭비, 잘못된 푸시 알림 등 **실전 사례 공유**가 길게 이어짐. 원인분석·재발방지·프롬프트 개선으로 수렴.
- **PPT 자동화 대토론 (P72 중심)** — 젠스파크 vs 아스트라 vs slides-grab vs 클코+구글슬라이드, 실패("무한 지옥")와 성공(zip→아스트라)까지 **가장 기술적으로 밀도 높은 스레드**.
- **우로보로스·소크라틱 인터뷰** — AI 지시문 품질 문제에서 **논문 5편**까지 연결된 심화 논의.
- **OpenAI 수학 증명 뉴스** — 5년 내 7대 난제, AI 자기증식 vs 수학 풀이 등 기대·불안 교차.

## 자동화·시스템 적용 후보

- **OpenClaw localhost 운영 패널**: 크론 / 스킬 / 일일 메모리 뷰어 탭 통합.
