# AI 요약

## 인사이트·노하우

- **Orca + OMP 조합 추천**: Orca 단독보다 OMP(Oh My Posh)를 함께 쓰면 모델별 계층 분리 및 역할 분담이 가능해 더 안정적. "Sol, Terra, Luna 나눠서 써야 됨"
- **Codex CLI/App 버그 주의**: 2026-07-14 기준 매일 업데이트 중이며 버그가 많음. OMP로 모델별 계층 분리해서 역할 나누는 방식이 현실적인 대안.
- **Orca 내 Claude 연동 밴 위험**: OMP에 Claude를 물리는 것은 애매하지만, Orca 내에서 터미널 CLI로 돌리는 것은 네이티브 사용으로 간주되어 밴 걱정 없음.
- **Orca Windows(WSL) 불안정**: WSL 워크스페이스에서 작업 시 hang 걸리는 이슈 다수 보고. macOS에서는 안정적.
- **Orca 커스텀 스킬 활용법**: Orca 내에서 오케스트레이션 시 `/codex-grok` 같은 커스텀 스킬을 만들어 Codex 감독자 + Grok 워커 구조로 구성하면 탭을 자동 생성해 티키타카 동작.
- **OMP vs 가재코드**: 가재코드는 OMP를 하드포크한 프로젝트. OMP가 컨트리뷰터가 더 많아 안정적.
- **MCP 서버 보안 체크리스트** (실제 스캔 포착 보고 기반):
  - 외부에 공개된 포트 여부 확인
  - `.env`, `mcp.json`이 GitHub에 올라갔는지 확인
  - API 키 평문 저장 여부 확인
- **글쓰기 모델 비교**: 글은 Claude가 자연스럽고, GPT는 딱딱한 편(무협소설 스타일). 용도에 따라 선택.

## 자동화·시스템 적용 후보

- **AI 구현 → 자동 테스트 → 사람 승인** 3단계 구조: 바이브코딩 납품·AI 서비스 설계의 기본 프레임으로 제안됨. 특히 광고·결제·회계 등 돈이 오가는 업무에 적합.
- **Orca 커스텀 스킬 `/codex-grok` 패턴**: Codex를 감독자, Grok을 워커로 지정하는 커스텀 스킬을 만들어 자동으로 탭을 열고 에이전트 간 티키타카 구조 구현.
- **텔레그램 + 마누스 연동**: 이메일 발송 + 이미지 생성을 마누스로 처리하는 텔레그램 봇 구성. 1,000 크레딧 이벤트 연계.
- **AI 서비스 기획 3문장 프레임워크**: (1) 어떤 반복 업무가 문제인가 (2) AI가 어디까지 대신하는가 (3) 사람은 무엇을 최종 승인하는가 — 이 세 문장으로 기획서·제안서의 절반 완성.
