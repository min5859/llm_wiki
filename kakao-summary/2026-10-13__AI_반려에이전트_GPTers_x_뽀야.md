# AI 요약

## 인사이트·노하우
- **Orca 멀티 에이전트 오케스트레이션 시 터미널 증식 및 메모리 부하 문제**:
  - **증상·원인**: GPT를 두뇌로 두고 Claude·Gemini를 오케스트레이션해 사용할 때 터미널을 수십 개씩 열어 메모리 부하로 다운됨. 어사이드(불명)까지 함께 돌리면 RAM이 버티지 못하며, 64GB RAM 리눅스 서버에서도 며칠 돌리면 지속적인 재부팅이 필요할 정도로 무거움.
  - **시도(한계)**: 작업이 끝난 터미널이나 idle 상태인 터미널을 닫으라고 지시해도 100% 작동하지 않음("뭐가 있어서 종료된거라 볼수 없어서 안닫았다"는 식으로 판단하거나 일시적으로만 따름).
  - **해결·우회책**:
    1. 스킬(Skill)에 백그라운드 작업을 지시하거나 `tmux`의 window/pane 중 명시해서 열도록 규칙을 적어둠.
    2. 무거운 Orca 대신 `tmux` 기반으로 전환(모바일 앱으로 연결해 작업하기에도 용이).
    3. 별도 리눅스 서버(RAM 64GB 등)를 세팅해 전용 서버로 분리.
    4. 터미널 하나를 상시 할당해 "1시간마다 한번씩 터미널 다확인해서 죽여줘" 태스크를 걸어두되, 다른 프로젝트 상황을 모르고 죽일 수 있으므로 "전체적으로 다확인하고 해줘"라고 조건을 부여.
- **클로바노트 데이터 보관 및 무료 시간 한도**:
  - 기기 내부에서 온디바이스로 텍스트 변환되는 방식이 아니라 네이버 서버에 저장되며, 데이터 수집에 동의하면 데이터가 넘어가는 구조.
  - 기본 무료 제공량은 월 300분이며, 데이터 수집 관련 동의 시 300분이 추가 제공됨(보안을 위해 동의하지 않고 다계정을 생성해 우회 사용 가능).
- **에이전트 프레임워크 간 체감 성능 차이**:
  - 동일한 `gpt 6.0 sol` 모델을 사용하더라도 최근 헤르메스(Hermes)는 성능이 크게 저하된 반면 오픈클로(OpenClaw)는 성능이 개선된 것으로 체감됨.

## 추천·자료
- **REA**: 소스 코드 없이 컴파일된 실행 파일, 안드로이드 앱, 웹사이트, 기기 펌웨어 등을 AI 에이전트가 직접 리버스 엔지니어링하여 기능 동작 원리를 분석하고 따라 만들게 해주는 오픈소스 도구(GitHub 스타 8만 개 이상).
- **노션(Notion) 회의록**: 회의 내용을 깔끔하게 잘 정리해 주는 회의록 도구.
- **tmux**: Orca 등 무거운 오케스트레이션 도구를 대체해 터미널 세션을 가볍게 관리하고, 스마트폰 앱과 연동해 원격 작업할 때 유용한 터미널 멀티플렉서.
- **herdr**: Orca의 대안으로 언급된 터미널·에이전트 관리 도구(단, 터미널을 여는 방식 자체는 Orca나 `tmux`와 유사함).
- **Windscreen VPN**: 무료로 사용 가능한 것으로 공유된 VPN 도구(불명).

## 자동화·시스템 적용 후보
- **보안 회의록 작성을 위한 로컬 마스킹·실명화 배치 파이프라인**:
  - 흐름: 클로바노트 회의 기록 수동 다운로드 → 로컬 배치 파일로 민감정보 마스킹 → Claude에 입력해 회의록 작성 → 로컬 배치 파일로 실명화(역마스킹) 복원.
  - 효과: 외부 LLM(Claude)에 기밀이나 실명을 노출하지 않고 파일 이동만으로 안전하게 회의록을 자동 생성(배치 스크립트 자체도 Claude로 생성).
- **유휴 터미널 주기적 정리(Reaper) 태스크 프롬프트**:
  - 오케스트레이션 도구 사용 시 전용 터미널 하나를 상시 실행해 두고, 1시간 주기로 `"전체 프로젝트 상황을 다 확인한 뒤 종료/유휴 터미널만 죽여줘"`라는 감시 태스크를 반복 실행하는 패턴.
- **에이전트 스킬(Skill) 내 터미널 실행 위치 고정**:
  - 에이전트가 새 터미널 창을 무분별하게 열지 않도록 스킬 정의 파일에 백그라운드 실행 또는 특정 `tmux` window/pane 지정을 명시하는 규칙.
