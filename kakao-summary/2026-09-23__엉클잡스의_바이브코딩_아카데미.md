# AI 요약

입력 텍스트만 기준으로 정리했습니다.

## 인사이트·노하우

- **AI 다이어그램: Mermaid 한계**  
  프로세스를 자꾸 Mermaid로 그려 답이 안 맞는 경우가 있음. 대안으로 `diagram-design` 스킬/레포를 Opus 5.5에 붙이면 체감이 크게 좋아진다는 공유(「날아다닙니다」).

- **「디자인 스킬」만으로는 한계**  
  디자인용 스킬도 결국 **지침**이라 단독으로는 큰 효과가 없다는 정리. 실무에서는 **컴포넌트 라이브러리·디자인 시스템**을 두는 편이 낫다.

- **향기 나는 UI를 만드는 구성(당사자 권장 흐름)**  
  1) **디자인 토큰** 정의  
  2) **Figma MCP** 또는 **pen dev**(원문 표기; 정확한 도구명은 맥락상 Figma·디자인 연동 도구로 이해됨)로 묶어 두기  
  3) **OpenDesign** 또는 **Claude Design**으로 디자인 시스템을 구축  
  → 이후 생성물이 「꾸릉내 나는 차트」「향기 나는 디자인」 수준으로 나온다는 경험담.

- **OpenAI `product-design` 스킬**  
  **시안(와이어/초안) 잡기**에 퀄이 좋다. 다만 **image-to-code** 변환 후 어색한 부분은 **미세조정이 필수**.

- **`impeccable` + Astra(도구/스킬명으로 언급) 사용 시**  
  중복 **카피라이팅·컴포넌트**가 자주 생김 → 지침에 **중복 제거**를 명시하면 시간을 아낄 수 있음. 「그나마 요고 개안습니다」 수준으로 상대적으로 낫다는 평.

- **Claude Design 체감(반대 의견)**  
  개인적으로 클로드 디자인 느낌이 별로, 「공대생이 만들어서」 촌스럽다는 평이 있음. 이에 대해 「공대생으로서 웁니다」— **결국 돌고 돌아 Figma**, **레퍼런스를 많이 참조**하는 것이 가장 낫다는 결론.

- **BMAD UX**  
  Sally BMAD UX **페르소나**를 메인으로 쓰는 사례(디자인·UX 지침용).

- **Opus 5.5 출시·한도**  
  Opus 5.5 출시 언급과 함께 **초기화권(사용 한도 리셋)** 지급, Codex **토큰 리셋** 완료 언급—추석 전후로 도구 업데이트·한도 이벤트가 겹친 맥락.

## 추천·자료

- **[diagram-design](https://github.com/cathrynlavery/diagram-design)** — Opus 5.5에 붙여 쓰기 권장. Mermaid 대신 **프로세스·차트 품질**을 올리려는 맥락.

- **[Claude Opus 5.5 시스템 프롬프트 공식 문서](https://platform.claude.com/docs/en/release-notes/system-prompts/claude-opus-5-5)** — 5.5 기본 동작·지침을 직접 확인·비교할 때.

- **[impeccable](https://github.com/pbakaus/impeccable)** — 디자인/프론트 관련 스킬 후보. Astra 등과 병행 시 **중복 컴포넌트·카피** 이슈는 지침으로 보완.

- **OpenAI `product-design` 스킬** — 초기 **시안** 품질이 좋다는 추천(이후 코드 변환은 손보기 필요).

- **OpenDesign / Claude Design** — **디자인 시스템 구축** 경로로 추천.

- **Figma + 디자인 토큰 + Figma MCP(·pen dev)** — 스킬만 믿지 않고 **시스템·토큰·피그마 연동**으로 가는 스택.

- **Sally / BMAD UX 페르소나** — UX·디자인 방향을 페르소나 지침으로 고정해 쓰는 사례.

## 반응이 컸던 화제

- **Opus 5.5 출시 + 초기화권·Codex 토큰 리셋** — 출시 기대와 한도 리셋에 호응이 큼. 「추석때 쉬게좀 놔둬라」는 **연휴에도 도구·한도 이슈가 쏟아지는** 공감.

- **Mermaid vs diagram-design** — 「머메이드가 별론데 자꾸 그걸로 프로세스 그려줘서」라는 **실제 pain point**에서 해결책 공유로 이어짐.

- **디자인 스킬·디자인 시스템 어떻게 쌓을까** — Sally/BMAD, product-design, impeccable, Claude Design 촌스러움, **결국 Figma·레퍼런스**까지 **도구 스택 토론**이 이어짐.

---

## 자동화·시스템 적용 후보

- **Opus 5.5 + `diagram-design`** — 내부 문서·프로세스 다이어그램 생성 파이프라인의 기본 스킬 세트.

- **디자인 토큰 → Figma MCP → (OpenDesign|Claude Design) 디자인 시스템** — UI 생성 전 **토큰·컴포넌트 라이브러리**를 먼저 두는 워크플로.

- **프론트/디자인 스킬 지침에 「중복 카피·중복 컴포넌트 금지/제거」** — Astra·유사 도구 사용 시 반복 생성 비용 절감.

- **BMAD UX(Sally) 페르소나** — UX 리뷰·와이어 지시를 **페르소나 고정 프롬프트**로 재사용.

- **5.5 system prompt 문서** — 다른 스킬·게이트와 **기본 행동 차이** 비교·회귀 테스트용 기준 문서.

## 질문·미해결

- **「Product design은 세르게이꺼를 쓰셨나요」** — 대화 로그에 **명확한 답 없음**(어떤 `product-design` 스킬/버전인지 불명).

- **「pen dev」** — 원문만으로는 **정확한 제품명 불명**(Figma MCP와 함께 언급된 디자인 연동 도구로 추정되나, 입력만으로는 확인 불가).

- **「Astra」** — impeccable과 비교된 대상의 **정체(스킬명·도구명)** 는 입력에 정의 없음.
