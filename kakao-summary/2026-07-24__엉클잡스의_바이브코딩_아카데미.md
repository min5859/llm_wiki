# AI 요약

## 추천·자료

- **Grok Build Workflows** — xAI의 코딩 에이전트 Grok Build에 추가된 대형 병렬 작업 처리 기능. 자연어로 요청하면 에이전트를 기본 128개, 최대 1,024개까지 병렬 실행하고 별도 '스켑틱' 에이전트가 결과를 검증한 뒤 리포트로 정리. 한 대화에 담기지 않는 대형 PR 리뷰·이슈 트리아지·코드베이스 전체 감사에 유용.
- **Claude Security 플러그인 (베타)** — 클로드 코드 세션 내 `/claude-security` 명령 하나로 저장소 전체 또는 diff를 스캔. 독립 검증 에이전트 3개 중 2개 이상 동의한 취약점만 보고서에 포함, 패치 파일 생성 후 `git apply`로 수동 적용. 바이브코딩 결과물의 보안 허점을 배포 전 점검하는 용도로 적합. (유료 플랜 + 클로드 코드 v2.1.154+, Python 3.9.6+ 필요)
- **오픈소스 아이콘 라이브러리** — 바이브코딩 시 UI 아이콘 조달용으로 채팅방에서 강추. [Threads 원문](https://www.threads.com/@jinsolisme1/post/DbKEe6iE-KW)
- **indiedevpersona.com** — 엉클잡스(P1) 공홈 최초 공개. 인디 개발자 퍼소나 관련 서비스로 보이나 상세 불명.

## 인사이트·노하우

- **Opus 4 성능 저하 징조 = 출시 임박 신호** — 여러 참가자가 "오푸스가 바보됐다"고 느낀 시점이 신모델 출시 직전과 겹치는 패턴. P1 해석: "컴퓨팅 자원이 부족해 이전 모델이 정상 작동 못 하는 것". 출시 전 임시 대안으로 Claude Sonnet 또는 Codex로 전환하는 전략 유효.
- **Grok Build Workflows 설계 원칙** — 에이전트 숫자보다 "이 작업이 정말 쪼갤 수 있는 일인지" 먼저 판단하는 것이 핵심. 워크플로는 `.grok/workflows/`(팀 공유) 또는 `~/.grok/workflows/`(개인용)에 저장 후 슬래시 명령으로 재사용 가능.
- **문샷AI의 Kimi K3 증류 논란** — 백악관이 앤트로픽 Fable 모델 무단 증류를 주장했으나, AI 연구자 다수가 "Fable 재공개 15일 만에 증류만으로 2.8조 파라미터 모델 완성은 불가"라고 반박. 오픈웨이트 모델 도입 시 공급망 이슈·규제 리스크를 함께 검토해야 함을 보여준 사례.
- **Suno 5,500만 명 개인정보 유출 (2025-11 발생, 2026-07-20 공개)** — 8개월간 이용자 미통지. Suno 계정 보유자라면 [Have I Been Pwned](https://haveibeenpwned.com)에서 이메일 확인 권장, 동일 비밀번호 타 서비스 즉시 변경.

## 자동화·시스템 적용 후보

- **Grok Workflows의 병렬 에이전트 + 스켑틱 검증 패턴** — 대형 작업을 독립 컨텍스트 에이전트로 분산 → 별도 검증 에이전트가 결과를 재확인하는 구조. 멀티에이전트 파이프라인 설계 시 참조 가능.
- **Claude Security의 다수결 검증 패턴** — 취약점 보고 기준을 "독립 에이전트 3개 중 2개 이상 동의"로 설정해 오탐을 줄이는 접근. 자체 에이전트 파이프라인에서 결과 신뢰도 기준 설계 시 참조.
- **배포 전 `/claude-security` 스캔 루틴화** — 바이브코딩 결과물은 커밋·배포 전 보안 스캔을 새 습관으로 추가하는 것 권장.

xAI 코딩 에이전트 Grok Build에 대형 작업을 통째로 병렬 처리하는 Workflows가 추가됐어요. 자연어로 작업을 요청하면 Grok이 단계별로 계획을 짜고, 에이전트를 백그라운드에서 병렬로 돌린 뒤 검증까지 마쳐서 리포트 하나로 정리해줘요.

━━━━━━━━━━

1️⃣ 에이전트 규모
· 기본 128개, 대형 작업은 최대 1,024개까지 동시 실행
· 참고로 기존 서브에이전트는 최대 8개 수준이었어요

2️⃣ 동작 방식
· 작업을 여러 단계로 나누고, 에이전트마다 독립된 컨텍스트에서 작업해요
· 완료된 결과는 별도의 '스켑틱' 에이전트가 다시 검증해요
· 메인 세션은 실행 중에도 그대로 쓸 수 있고, 일시정지 후 재개해도 끝난 작업은 다시 안 해요

3️⃣ 확인·재사용
· /workflows로 단계별 진행률 + 에이전트별 토큰 사용량 실시간 확인
· .grok/workflows/에 저장하면 팀 공유, ~/.grok/workflows/는 개인용
· 저장한 워크플로는 /pr-review 5137처럼 슬래시 명령으로 바로 재사용돼요

4️⃣ 덤으로
