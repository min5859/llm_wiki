# AI 요약

## 인사이트·노하우

- **Pi(AI)의 MCP 노선 변경**: Pi는 경량화·불필요한 요소 제거(린)·효율/속도를 중시하는 철학 때문에 MCP에 회의적이었음 — "컨텍스트만 차지한다"는 이유. 최근 Pi가 MCP 지원으로 노선을 변경했는데, **Codemode + Jev**가 결합된 형태로 연결되는 방식이라고 함. 관련 개념으로 **PTC**가 언급됨(정확한 정의는 본문에 없어 불명).
- **Claude 자습서(dev.claude 문서/블로그) 활용법**: Codex 위주로 작업하는 사람이 "명령어 제외하고 참고자료로 써도 되는지" 질문 → 답변: Claude 블로그·문서는 "서로 맞물려서 빌드업"되는 구조라, 명령어 자체보다 **흐름과 내용을 파악하는 것**이 도구와 무관하게 도움이 된다는 조언.
- **GPT(혹은 Sonnet) 성능 저하 체감 보고**: 한 참가자가 "엊그제 새벽 4시 30분부터" 이상 증상을 감지하고 그 이후로는 Codex로 작업을 전환했다고 실시간 공유. 같은 날 다른 참가자도 "쏠(Sonnet) 6.1이 느려진 것 같다"는 체감을 보고 — 복수 인원이 비슷한 시점에 품질 저하를 느낀 사례.

## 질문·미해결

- **PTC가 정확히 무엇인지**: 본문에서 언급만 되고 설명되지 않음(불명).
- **Codemode + Jev 결합 구조의 세부 동작 방식**: Pi의 MCP 연결 방식이 구체적으로 어떻게 작동하는지는 원문 요약만 있고 상세 불명.
- **GPT astra / Sonnet 6.1 성능 저하가 실제 모델 변경에 의한 것인지, 일시적 현상인지**: 참가자들의 체감 보고만 있고 원인 분석이나 공식 확인은 없음.
