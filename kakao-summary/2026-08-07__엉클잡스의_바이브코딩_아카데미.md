# AI 요약

## 인사이트·노하우

- **네이버 블로그 자동 게시의 API 제약**: 스레드(Threads)는 API를 제공해 자동 게시가 가능하지만, 네이버 블로그는 API가 막혀있어 자동화가 어렵다는 것이 확인됨. 클로드/코덱스의 컴퓨터 유즈(Computer Use)로 우회 자동 게시는 가능하나, 컴퓨터/서버가 항상 켜져있어야 함.
- **악보 인식은 VLM/OCR의 병목 지점**: 일반 비전/OCR 모델은 텍스트는 잘 읽지만 악보 인식은 처참한 수준. 손으로 그린 게 아닌 정형 악보라면 OCR/VLM 대신 악보를 코드처럼 파싱하는 전용 방식이 필요하다는 의견(`손으로 그린게 아니면 OCR이나 VLM으로 읽는게아니라 악보를그대로 코드처럼 읽게하면안되나요`).
- **음성 분석 AI의 한계**: 제미나이에 녹음 파일을 올리면 STT를 넘어 간단한 분석까지 해주지만, 단순 진폭 기반이라 잡음이 섞이면 정확도가 떨어짐. 디테일한 보컬 코칭에는 부족.
- **Claude 구독 주간 초기화 시점이 결제 요일과 다를 수 있음**: 한 참가자는 금요일에 결제했는데 초기화는 목요일에 발생하는 것으로 관측됨(앤트로픽 공식 문서에는 관련 내용 없음). 취소해도 결제한 기간까지는 이용 유지된다는 점은 확인됨.

## 추천·자료

- **OpenCodex**: OpenAI Codex(컴퓨터 유즈 지원, 화면을 보고 클릭/입력, 아이폰 미러링 원격 조작 가능)의 "슈퍼앱" 틀에 Claude 모델을 이식할 수 있게 해주는 오픈소스 프로젝트. 급부상 중이라고 소개됨.
- **aside**: 네이버 블로그 자동 게시를 지원한다고 언급된 도구. 맥(Mac) 환경에서만 사용 가능.
- **MIDI 검색·변환 팁**: 영미권 찬양곡·클래식·팝송은 "곡 제목.midi"로 검색해 MIDI 파일을 구한 뒤, 웹상 MIDI 플레이 사이트에서 재생/확인하는 방식이 가능. 악보 전문 OCR 프로그램으로 1차 제작 후 가공하는 방법도 대안으로 제시됨(한국 찬양곡은 자료가 부족할 수 있음).

## 반응이 컸던 화제

- **P13의 3시간 인터뷰 후기**: 왕초보에서 시작해 개발보다 영업에 재능을 발견했다는 후기에 다수가 축하 반응. "영끌님", "영업의 신" 등 애정 어린 놀림 섞인 축하가 이어짐(1년 전만 해도 컴퓨터를 다룰 줄 몰랐다는 점이 공감/응원 포인트).
- **악보 인식 → 미디 피아노/가이드 보컬 생성 논의**: 교회 악기팀 활동을 위해 악보를 인식해 미디 피아노나 가이드 보컬을 생성하고 싶다는 질문에 여러 명이 참여. 악보 인식의 기술적 난이도(OCR/VLM 한계), 기존 도구 유무, MIDI 검색 대안까지 여러 차례 주고받으며 구체적 해결책 탐색으로 이어짐.
- **보컬 트레이닝 AI 자체 제작**: 학원 두 달보다 제미나이 3일 활용이 더 효과적이었다는 경험을 계기로 보컬 코칭 프로그램을 직접 만들어보고 있다는 이야기에 관심 반응("좋은데요", "굿입니다"). 다만 "만들다보니 요구사항이 계속 커진다"는 스코프 크립(scope creep) 경험도 공유됨.

## 자동화·시스템 적용 후보

- **컴퓨터 유즈 기반 블로그 자동 게시**: 클로드/코덱스에 "알아서 올리라"고 지시하면 컴퓨터 유즈로 실제 게시까지 수행 가능(단, 서버/PC 상시 구동 필요) — 다른 콘텐츠 자동 발행 워크플로에도 참고 가능한 패턴.
- **악보 인식 파이프라인 설계 아이디어**: OCR/VLM 대신 악보를 구조화된 코드로 직접 파싱하는 방식 + 실패 시 MIDI 파일 검색으로 대체하는 하이브리드 접근이 제안됨.

## 질문·미해결

- 네이버 블로그를 API 없이 완전 자동으로 게시하는 구체적 방법 — "분명 하고 있는 사람은 있는 것 같은데 방법을 모르겠다"는 상태로 미해결.
- Claude 구독의 주간 초기화 요일을 결제일 변경 없이 조정할 수 있는지 — 공식 문서에 명시된 바 없어 불명.
- 악보(특히 손글씨가 아닌 정형 악보) 인식을 안정적으로 처리해주는 기존 도구가 실제로 쓸만한지 — GPT가 제시한 후보들을 재검증 예정("다시 해보겠습니다")이었으나 결과는 대화 내에 없음.
