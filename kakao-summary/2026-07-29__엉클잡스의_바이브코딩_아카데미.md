# AI 요약

## 인사이트·노하우

- **PDF 번역 파이프라인**: 번역 자체는 어떤 AI든 잘 하지만, **PDF에서 텍스트를 추출하는 것이 핵심**. 특히 100페이지 분량 데이터시트 같은 경우:
  - 추천 조합: **업스테이지 API + OpenDataLoader** (직접 비교 테스트 결과 가장 성능 우수)
  - 업스테이지 API는 무료 사용량 제공
  - 대안: ilovepdf (무료 사용량), 안티그래비티 CLI (미디어에 강함)
  - 단순 번역이라면 Claude Code에 PDF를 바로 던져서 번역 요청도 유효

- **Kimi K3 라이선스 주의**: "공개됐다"와 "상업 이용 가능"은 다름. 연 매출 2천만 달러 초과 모델 서비스 사업자는 별도 계약 필요, 월간 활성 이용자 1억 명 이상 제품은 UI 표기 의무. 오픈 웨이트 모델 도입 시 **성능보다 라이선스 먼저 확인**.

- **에이전트 권한 설계 원칙**: "에이전트를 많이 만드는 것보다 무엇에 접근했고 얼마를 썼는지가 중요해졌다." 읽기 권한과 쓰기 권한을 분리하는 것이 기본.

- **로컬 AI 자동화 시작 방법**: 반복 업무를 "읽기만 하는 자동화"로 먼저 구성 → 삭제·이동 등 변경 작업은 직접 승인하는 방식으로 안전하게 시작.

## 추천·자료

- [업스테이지 + OpenDataLoader PDF 번역 비교 유튜브](https://youtu.be/V8P2d4dtYDs) — 두 도구를 직접 비교한 영상. 100페이지 분량 PDF 번역 작업 시 가장 신뢰할 수 있는 실측 레퍼런스.
- [opendataloader-pdf](https://github.com/opendataloader-project/opendataloader-pdf) — PDF 텍스트 추출 특화 도구. 업스테이지 API와 조합 시 성능 우수.
- [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) — 이미지 기반 PDF나 스캔 문서의 텍스트 추출에 사용 가능한 OCR 라이브러리.
- [Buzz (잭 도시)](https://www.threads.com/share/FoiE1wyec/) — 트위터 창시자 잭 도시가 만든 슬랙 대안. 슬랙 요금제 부담을 줄이려는 팀에게 검토 가치 있음.
- [Kimi K3 (문샷)](https://github.com/MoonshotAI/Kimi-K3) — 전체 파라미터 2.8조 개, 활성 1,040억 개, 100만 토큰 문맥, 멀티모달 지원 오픈 웨이트 에이전트 모델. 단, 전용 라이선스 적용.

## 반응이 컸던 화제

- **PDF 번역 도구 문의 → 실전 솔루션 공유**: 단순 질문이 구체적인 도구 비교(ilovepdf / opendataloader / PaddleOCR / 업스테이지 API)와 실측 유튜브 링크 공유로 이어짐. 실무 필요가 명확해 정보 밀도가 높았음.
- **Kimi K3 돌풍과 AI 모델 경쟁**: "누가 이길지 도무지 예측이 안된다", "빠르게 바뀌니 따라가기 벅차다"는 공감대 형성. 라이선스 함정 포인트도 함께 논의됨.
- **Buzz (슬랙 대안)**: 잭 도시 언급과 함께 바로 설치·테스트하는 참가자 등장. 슬랙 요금 부담에 대한 공감이 즉각 반응으로 이어짐.

## 자동화·시스템 적용 후보

- **PDF 번역 파이프라인 패턴**: 업스테이지 API(텍스트 추출) + OpenDataLoader(파싱) + 임의 LLM(번역) 조합. 100페이지 이상 기술 문서(데이터시트, 논문)에 바로 적용 가능.
- **에이전트 자동화 설계 원칙**: 읽기 전용 자동화 → 변경 작업 수동 승인의 단계적 도입 패턴. 신규 자동화 도입 시 기본 템플릿으로 활용 가능.
