# AI 요약

## 인사이트·노하우

- **오픈클로(OpenClaw) 7.1 업데이트**: GPT-5.6 사용 가능, 온보드 명령어 변경, 컨텍스트 100만 토큰 지원.

- **오픈클로 최소 사양**: 봇 1개당 RAM 4GB 내외 소모. 8GB로도 구동 가능(P42 실증). 그래픽카드 불필요. WSL 환경(Windows)에서도 동작.

- **오픈클로 초기 보안 설정 권장사항**: 파일 삭제 금지, 파일 수정 시 백업, 외부 전송·로그인·결제 금지를 초기 설정에 명시적으로 박아두면 리스크 완화 가능. "모든 에이전트는 내 컴을 마음대로 주무를 수 있어서 위험은 항상 있지만 주의해서 사용하면 됨 = 클코 코덱스도 마찬가지."

- **오픈클로 크론잡 안정성**: 오픈클로 크론잡을 많이 만들면 리눅스가 프로세스를 죽이는 문제 발생 → 오픈클로 내부 크론잡 대신 **리눅스 크론탭으로 옮기면 해결**됨 (P42 실증).

- **헤르메스 권장 모델**: GPT, Grok 계열 추천. Gemini는 정지 이슈, Claude는 막혀 있음(OAuth 구독 기준).

- **오픈라우터 특성**: 종량제. 중국 모델을 미국 호스팅으로 사용 가능하다는 장점. Claude 계열 연결 시 토큰이 빠르게 소진됨.

- **페이블(Fable) 소진 시 대안 워크플로**: 설계는 GPT-sol로, 코딩은 Claude Code(Opus 4.8)로 분리. 또는 `claude -p`로 단계마다 교차검증하는 방식도 유효.

- **GitHub PAT 유출 이슈 (2026-07-14)**: GitHub Personal Access Token 유출 사고 발생. [github.com/settings/tokens](https://github.com/settings/tokens)에서 발급된 PAT 점검 필요.

- **노션 API / 구글 캘린더 API 인증 풀림 문제**: 설정 변경 시 반복적으로 풀리는 현상 보고됨. 해결책으로 **device code 방식 활용** — 외부에서 인증/로그인할 수 있는 링크를 에이전트에게 요청하는 방식(P55 제안). 노션 API 코드 자체가 바뀌지 않는 이상 API 키는 원래 유지되어야 하므로 설정 방식 점검 필요.

- **Orca IDE**: 터미널 멈춤 버그가 윈도우 환경에서 주로 발생. 재실행해도 멈춤 상태 유지됨. 클린 삭제를 안 하면 다른 환경에서 Orca 훅을 잡아버려 문제 생기는 케이스도 있음. 맥 환경에서는 상대적으로 안정적. YC 투자사이며 업데이트 주기 빠름.

## 반응이 컸던 화제

- **Orca IDE 터미널 멈춤 버그**: 여러 명이 동일 증상 경험을 공유하며 "윈도우 한정인지", "재실행해도 안 고쳐지는 문제"를 집중 토론. 실사용자들이 맥으로 회귀하거나 다른 IDE로 이탈하는 계기가 됨. 버그 공감대가 커서 길게 이어짐.

- **오픈클로·헤르메스 PC 구매 필요 여부**: 신규 입문자(P67)의 질문에 다수가 "꼭 살 필요 없다"며 직접 경험담을 공유. FOMO 심리 vs 실제 필요 여부를 현실적으로 짚는 조언들이 연달아 나옴.

## 자동화·시스템 적용 후보

- **오픈클로 크론잡 → 리눅스 크론탭 이관 패턴**: 오픈클로 내부 크론잡이 리눅스 OOM killer에 의해 죽는 경우, 작업을 리눅스 시스템 크론탭으로 옮기면 안정화됨. 오픈클로를 헤비하게 운용할 때 고려할 아키텍처 결정.
- **Claude -p 교차검증 패턴**: `claude -p` 옵션으로 단계마다 별도 프로세스를 띄워 결과를 교차검증. 단일 모델 예산 소진 시 대안 워크플로로 활용 가능.
- **device code 인증 링크 요청 패턴**: API 인증이 반복적으로 풀릴 때 에이전트에게 "device code 방식으로 외부 인증 링크 달라"고 요청하면 세션 밖에서 재인증 처리 가능.

## 질문·미해결

- **노션 API / 구글 캘린더 인증이 설정 변경 시마다 풀리는 근본 원인**: 명확한 원인이 대화 내에서 규명되지 않음. 노션 API 키 자체는 코드 변경 전까지 유지되어야 하므로 설정 저장 방식 또는 에이전트 컨텍스트 초기화 문제로 추정되나 불명.
- **Orca 터미널 멈춤 버그**: 재실행해도 멈춤 상태가 유지되는 근본 원인 및 해결책 미확인. 윈도우 한정 이슈인지도 확정되지 않음.
- **오픈클로에서 코덱스 외 다른 모델 사용하는 소스**: P24가 "코덱스에서 다른 모델 쓰는 소스도 있던데"라고 언급했으나 후속 논의 없이 종결.
