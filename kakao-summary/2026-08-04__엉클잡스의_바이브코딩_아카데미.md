# 엉클잡스의 바이브코딩 아카데미 — 2026-08-04 대화 정리

## 인사이트·노하우

- **LLM 백엔드 조합 추천 (P2)**: 외출 시 `Orca + Herdr + Omp/ClaudeCode`, 작업 시 `Ghostty + Herdr + Omp/ClaudeCode`, 상시 운영은 `VPS + TailScale + Telegram + HermesAgent` 구성. "네이티브는 아직 불안정해서 잠깐 놔뒀다"는 언급 있음. Herdr는 CPU 부하를 90% 가까이 절감했다는 평가.
- **가성비 LLM 논쟁**: 키로(Kiro) 코딩 플랜으로 헤르메스를 돌리면 rate limit이 빨리 닳는다는 불만에 대해, 딥시크(딥시기)+Flash 조합이 현재 "커트라인"이라는 의견(P2). CommandCode의 $1 플랜은 코딩 작업이 아니면 충분히 여유롭다는 팁도 공유됨.
- **카카오톡 대화 아카이빙/자동화 아이디어**: 카톡은 공식 내보내기 API가 없어 수동 내보내기만 가능(P2). 대안으로 안드로이드 공기계(중고 요금제 월 690원, 사진 2장으로 개통) + notification 권한을 받아 실시간 수집 파이프라인을 구축하는 방법이 논의됨(P25, P21). 공폰에 "미니스"를 깔고 cron을 걸면 자동화 가능하다는 제안(P6). 다만 "결국은 휴먼터치로 지식을 주입해야 한다"는 게 P2의 결론 — 비정형 대화를 전부 흡수하기보다 정형화/취사선택이 필요하다는 입장.
- **omp(하네스) 사용 팁**:
  - 간단한 작업도 기본적으로 TODO를 만들어 시간이 오래 걸리는데, 키미(Kimi)나 Composer로 돌리면 이 지시를 무시하고 빠르게 끝낸다. GPT는 TODO 지시를 잘 따라서 오히려 간단 작업도 느려지므로, 옵션으로 끄는 것을 권장(P39).
  - 오케스트레이션이 필요하면 `workflowz` 기능을 쓰면 좋다(P39).
  - Composer는 하네스가 굳이 필요 없다고 판단하면 지시(예: TODO 도구 사용)를 무시하는 경향이 있다는 실측 공유(P39, "재미로 테스트한 결과").
  - **한국어 입력 버그**: omp에서 한국어로 입력하면 "울보"(우로보로스 MCP)가 자동으로 호출되는 문제가 있어 영어로만 입력해야 한다는 팁(P2, P32). 원인은 우로보로스를 헤르메스에 설치했는데 거의 모든 CLI에 전역 적용되도록 설치되어버린 것(P1).
- **하네스 비교 (Orca / Paseo / Muxy / Terax)**:
  - `terax`는 한글 입력 버그로 "지금 금지" 상태(P13).
  - `muxy`는 가볍지만 기능이 부족해 "버리는기술"로 평가(P13).
  - `paseo`는 herdr의 더 깔끔한 버전이라는 평가, local+VPS를 모바일로 중앙화하는 UX가 강점. Orca보다 모바일 경험이 좋고 깃헙 스타도 준수하다는 평가(P13). Orca 설치 30분 만에 폐기하고 Paseo로 넘어간 사례도 있음(P25). 단 한국어 지원은 미흡해 개발자에게 피드백을 보냈다는 언급.
  - 최종 정리(P2): `1. muxy+herdr+moshi / 2. paseo / 3. orca` 세 가지 조합을 병행 구축, "omp가 지금 최고 하네스"라는 평가.
- **모바일 연동 도구 moshi**: 세션 내역 확인, 파일/이미지 전송 가능. 무료 티어 있으나 "big5" 등 고급 기능은 유료(P13). 유료 결제 타이밍을 놓쳐 평생권(11만원)이 아닌 연간권(약 29,000원)을 구매한 사례 공유.
- **Mole(몰레) 툴**: 맥 사용자 필수템으로 언급됨(P2, P13). `sudo mole clean` 명령이 언급됨. 컨설팅 방문 시 "윈도우에 mole부터 돌린다"는 활용 사례(P13).
- **GPU 클라우드 결제 트러블 해결 사례 (P38)**: Gcube(클라우드 GPU 대여 서비스)에서 2만원 충전 후 영상 생성 결과물이 모두 유실됨 → GPT에게 항의하자 클레임 이메일을 작성해줌 → 실제 발송 후 2만 포인트 환불받음. "전에는 컴플레인 메일을 GPT가 써줘도 성과가 없었는데, 실제 성과가 있었던 건 처음"이라는 코멘트.
- **바이브코딩 학습 조언 모음**:
  - "목적이 진짜 중요하다. 트렌드 때문에 하는 건 비추" (P2)
  - 판매/SaaS 목적이면 체계적 학습(CS 등), 개인 사용 목적이면 부딪히며 도메인 지식을 늘리는 게 좋다는 구분(P7)
  - 업무 분류 프레임워크(P7): "1) 시작부터 끝까지 내가 해야 하는 일(AI에 못 맡김), 2) 결정/피드백만 하면 되는 일(과정은 AI, 효율 소폭 상승), 3) 기계적이고 컨펌 불필요한 일(효율 대폭 상승)" — 본인 업무 비중을 먼저 파악할 것을 권장.
  - 효율성 메타인지 방법(P2, P10): 남과 비교하지 말고 인풋 대비 아웃풋, 시간 소모를 직접 측정할 것. 업무를 md화해서 트래킹하고 매일 AI에게 회고를 시키는 방법, 아침에 투두 10개를 세션에 한꺼번에 던져 "한계체험"을 해보는 방법도 공유됨(단, "일이 미친듯이 많아진다"는 부작용도 언급).
  - 1시간 일하고 10분 휴식 습관 공유(P10).
  - 비개발/비디자이너가 바이브코딩 용어(예: "네오브루탈리즘")를 익히면 프롬프트 작성이 훨씬 효율적이라는 팁(P7): "선굵고 비비드한 색으로 레트로 느낌나게 해줘"를 "네오브루탈리즘 한방"으로 대체 가능.

## 자동화·시스템 적용 후보

- **카카오톡 실시간 수집 파이프라인**: 안드로이드 공기계(저가 요금제) + 앱 notification 권한으로 대화를 실시간 캡처 → 룰베이스 키워드 추출/제외 키워드 필터링 → 파이프라인 적재. 현재 P21이 룰베이스를 다듬는 중이며, "사진 2장" 같은 패턴으로 인물 카운팅도 하고 있음.
- **GWS(구글워크스페이스) + AI 자동화 조합**: `GWS CLI + ClaudeCode` 또는 `GWS CLI + Hermes + Telegram` 조합으로 구글 워크스페이스 업무 자동화 가능(P2 아티클 참고). Apps Script(clasp)를 클로드코드에게 설치·작성시켜 시트/폼 자동화도 가능(P37).
- **업무 트래킹 + 회고 자동화**: 업무를 md 파일로 기록 → 매일 AI에게 회고를 요청 → 리뷰를 반복해서 파고드는 방식(P10). 아침에 하루치 투두를 한 번에 여러 세션에 던져 처리 한계를 테스트하는 방법도 언급.
- **AI 기반 클레임/컴플레인 메일 자동화**: 메일 작성부터 발송, 회신 알림까지 AI에게 맡기고 사람은 답장만 확인하는 워크플로우(P38) — 실제 환불 성공 사례로 검증됨.
