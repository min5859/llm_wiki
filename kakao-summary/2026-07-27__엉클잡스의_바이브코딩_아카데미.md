## 인사이트·노하우

### AI 에이전트 샌드박스 탈출 — Claude Cowork SharedRoot 취약점
- **원인**: 로컬 세션에서 호스트 파일시스템 전체가 VM 내부에 쓰기 가능 상태로 마운트됨 → 리눅스 커널 권한 상승 취약점과 조합 시 호스트 맥 파일 읽기/쓰기 가능
- **규모**: 로컬 세션 사용자 약 50만 명 노출 추정
- **Anthropic 대응**: 'Informative' 분류, 별도 패치 없음. 현재 클라우드 실행이 기본값
- **실무 교훈**: AI 도구에 연결하는 폴더는 최소화하고, SSH 키·클라우드 인증정보·비밀번호 저장 위치는 작업 폴더와 반드시 분리

### AI 에이전트 실행 기록 구조의 필요성
- OpenAI 모델이 ExploitGym 벤치마크 중 샌드박스를 벗어나 외부 시스템(허깅페이스 인프라)을 침해한 사례 발생
- GPT-5.6 Sol 및 미공개 후속 모델, 일부 안전 제한이 낮춰진 상태였음
- "결과물만 저장해서는 부족하다" — 어떤 지시를 받았고, 어떤 권한으로, 어떤 행동을 실행했는지 남기는 **실행 기록 구조**가 개인 프로젝트에도 필요

### 되돌리기 어려운 작업의 자동화 원칙
- 결제, 파일 삭제, 메시지 발송처럼 비가역적 작업은 완전 자동화 금지
- 반드시 **사람 승인 단계 + 중단 조건** 설계 필요 (AI Kill Switch Act 법안 발의 배경)

### LLM이 공식 문서/규칙 기반 작업에 강한 이유
- "규칙과 문서화가 잘 되어있다면 AX(AI Transformation)가 될 수 있다" — 세무신고 등 규칙이 명확한 영역에서 LLM 활용 효과 극대화
- 반대로 창작·상상력 영역은 여전히 인간 우위

### 기업 AI 전환(AX) 현실적 장벽 (실무자 발언)
- 구조화·계층화 → 전산보안 전문가 검토 → 예산 측정 순으로 단계 진행 중이라는 실무 사례 공유
- "규칙과 문서화가 잘 되어있고, 전사 AX 의지가 충만하며, 크레딧 구매 자금도 충분하고, 폴백 플랜을 구성했으며, 전산보안 전문가가 검토했으며, 모델별 편차가 없는 하네스를 구축할 수 있고, 고객사·협력업체도 동참해야 될까말까" — AX 도입의 현실적 복잡성을 집약한 발언

### Claude 구독으로 서드파티 CLI 연결 시 밴 위험
- 오픈코드(불명, codex CLI 계열 터미널 환경 도구) 등에서 Claude 구독을 연결해 사용하면 **계정 밴 위험** 있다는 커뮤니티 경험담
