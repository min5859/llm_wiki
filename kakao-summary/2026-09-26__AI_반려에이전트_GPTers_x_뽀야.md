# AI 요약

## 인사이트·노하우

- **헤르메스 Slack 연동 시 DM에 댓글(스레드 답장)이 달리는 문제**
  - 증상: 헤르메스를 Slack에 연결했을 때 DM에도 댓글(스레드 답장)로 응답이 달림. 새 메시지로 받고 싶어도 안 됨.
  - 해결: 헤르메스에게 "Slack 설정 변경 권한"을 주고 직접 수정을 요청하면, `reply_in_thread` 설정값을 `false`로 바꿔서 스레드 댓글 대신 새 메시지로 올리도록 변경 가능.
  - 주의: 설정값 변경 자체는 바로 저장되지만, **게이트웨이 재시작이 승인되지 않으면 실행 중인 봇에는 즉시 적용되지 않음** — 재시작이 허용되거나 다음 게이트웨이 기동 시점에야 반영됨.
  - 참고로 Slack 연동 자체(채널 글쓰기, 앱 설치 등)는 Slack CLI를 쓰거나 "aside"에게 시키면 가능하다는 의견도 있었음.

- **용도별 메신저 분리 전략** (P5 공유): "dm은 텔레그램, 단톡은 디스코드, 스레드는 슬랙" — 각 메신저의 강점(텔레그램=DM 편의성, 디스코드=단체방, 슬랙=스레드 기능)에 맞춰 에이전트 알림 채널을 나눠 쓰는 방식.

## 추천·자료

- **오픈클로(OpenClaw) vs 헤르메스(Hermes)** 사용 비교 (복수 사용자 공유): "둘다 사용중인데 개인적으로 별 차이없는듯"하며, 혼자 쓸 땐 오픈클로(최근 드리밍 기능 추가로 발전), 팀원들과 같이 쓸 때는 헤르메스를 선호한다는 의견. 처음 입문자는 "가볍게 찍먹"해보며 둘 다 만져보는 걸 추천.
- **초보자용 하드웨어/운용 방식 가이드**: LLM만 쓸 거면 구형 노트북도 충분하고, 웹브라우저 제어 등 에이전트 작업이 필요하면 최신 컴퓨터가 유리. 단순 반복작업 자동화는 초기 세팅(파이썬 스크립트 등)만 잘하면 지속적인 API/LLM 사용량이 거의 없다는 조언. 로컬 LLM은 "다다익램"(램 많을수록 좋음)이라는 공감대가 있었으나, 맥미니 M4 Pro 64GB로도 로컬 구동이 답답해서 결국 오어스(OAuth) 기반 구독 + 비상용 API 백업으로 전환했다는 실사용 후기.
- **에이전트 다중화 운용 예시** (P2): 코덱스/클로드/클로드API 3개 에이전트를 역할별로 분리 운용 — 코덱스 1개, 클로드 구독 1개, 클로드 API 1개로 비상 대비.

## 반응이 컸던 화제

- **사용량 리셋 시간 추측 소동**: 코덱스(Pro×20 등) 사용량 리셋 시점을 두고 여러 참가자가 "오늘 2시다", "5시다", "29일이다" 등 각자 다른 정보를 공유하며 장시간 토론. 리셋 시간이 공식적으로 명확히 공지되지 않아 혼란이 큼. "티보가 리셋할 거란 말만 했지 날짜는 안 박았다"는 코멘트처럼, 공식 소스(오픈AI 관계자 "티보")의 모호한 발언이 추측을 부추긴 상황.
- **"클로드가 무제한 모델을 풀면 코덱스를 떠날 것인가"**: 클로드가 월 500달러대 무제한급 요금제를 낼 수 있다는 소식에, 코덱스 이용자들 사이에서 전환 여부에 대한 기대와 논쟁이 있었음.
- **오픈클로 vs 헤르메스 비교**: 신규 입문자의 질문에 다수가 자신의 사용 경험을 공유하며 활발히 답변(각자 "개취"라는 결론이지만 토론 자체는 길게 이어짐).
- **로컬 vs API 사용 논쟁**: 초보자의 맥미니 사양 질문에 다수가 각자의 사용 목적별 기준(단순 작업=저사양 가능, 렌더링 등 무거운 작업=고사양 필요)을 제시하며 길게 답변.
