## 인사이트·노하우

- **Command Code + GLM Flash 응답 지연**
  - 증상: `effort off` 상태에서도 답변에 3분 이상 소요. 라우트별 측정값 — `glm-main (z-ai/glm-5.3-flash)` **52.0초**, `ds-main` **1.5초**.
  - 시도·관찰: 헤르메스 문제인지 의심했으나, 같은 시기 여러 사용자가 Command Code + GLM 조합에서 동일하게 느리다고 보고.
  - 원인 추정(미확정):
    1. 할인 이벤트로 이용자가 몰려 서버·라우트가 포화된 상태일 수 있음.
    2. 커뮤니티 쪽에서는 "모델에 물탄 것 같다"는 언급도 있음(공식 확인 없음).
  - 대안 체감: **OpenCode(오코)에서는 같은 GLM이 아직 빠르게 동작**한다는 보고가 있음 → 클라이언트·라우트·백엔드에 따라 체감이 크게 갈릴 수 있음.

- **Cursor 요금제와 Grok bot**
  - Ultra 없이도 Grok bot 사용 가능하다는 공유가 있음.
  - 다만 Pro로 내려가면 Grok bot **할당량이 줄어들었을 가능성**은 있음(Ultra 때는 여러 봇을 돌려도 사용량이 거의 안 보였다는 체감).

- **바이브코딩·에이전트 트렌드(브리핑 요약)**
  - 당일 GitHub 트렌딩 흐름: "더 큰 모델"보다 **덜 짜는 규칙**, **구조·흐름을 그림으로 남기는 스킬**, **과학 작업용 스킬** 쪽이 주목받는 날이었다는 정리.
  - 구직·자동화도 "별도 웹앱"보다 **이미 쓰는 코딩 에이전트 위에 얹는 형태**가 반복적으로 등장하는 패턴으로 언급됨.
