# 스코어 알고리즘 두 버전 비교 — 컷오프 캘리브레이션 vs 진짜 알파 변화

스크리너 점수 알고리즘을 V2 → V3 로 바꾼 직후 평균 점수가 17점 하락 (47 → 28) 하여 기존 컷오프 62 통과 종목이 0건이 됐을 때, **이게 "효과 있는 재설계" 인지 "단순 평행이동" 인지** 를 정량적으로 판정하는 방법론.

## 문제 설정

- V2 (기존): 평균 ~47, 최대 ~70, 매일 6~21건이 컷오프 62 통과 → 정상 매수 진입
- V3 (재설계 후): 평균 ~28, 최대 ~51, 매일 0건이 컷오프 62 통과 → 매수 정지
- 표면적 결정: 컷오프를 62 → 48 로 낮추면 V2 와 동등한 진입 빈도 복원

**핵심 질문**: 컷오프만 낮추면 V2 와 동일한가, 아니면 V3 가 의미 있는 알파 변화를 만들었는가?

## 비교 방법론 — 4가지 측정

### 1. 순위 상관 (Spearman ρ) — 가장 중요

동일 종목이 V2 와 V3 에서 어느 정도 같은 순위를 받는지.

```python
# 일별 종목 점수 매칭 (V2 = 직전 측정일, V3 = 첫 적용일)
pairs = match_by_stock(v2_scores, v3_scores)  # n=30

def rank(xs): ...  # 동순위 평균 랭크
def pearson(xs, ys): ...

v2_tot_rank = rank([p.v2_total for p in pairs])
v3_tot_rank = rank([p.v3_total for p in pairs])
rho = pearson(v2_tot_rank, v3_tot_rank)
```

- ρ ≈ 1.0 → 완전 평행이동 (컷오프 조정과 동등)
- ρ ≈ 0.0 → 완전 재정렬 (V3 가 진짜 다른 알고리즘)
- 실측: **ρ = +0.835** (강한 순위 보존, but 일부 reordering 존재)

### 2. Top-N 픽 교집합

각 알고리즘이 상위 N 종목으로 뽑는 후보의 겹침. 매수 후보 결정은 결국 Top-N 의 문제이므로 직접 영향 지표.

```python
v2_top = sorted(pairs, key=lambda p: -p.v2_total)[:10]
v3_top = sorted(pairs, key=lambda p: -p.v3_total)[:10]
overlap = set(v2_top) & set(v3_top)
print(f"Top-10 교집합: {len(overlap)}/10")
```

- 실측: 8/10 (80%) — 컷오프 단순 하향만 해도 매수 후보의 80% 는 동일

### 3. 큰 순위 이동 종목 — V3 효과 식별

```python
v2_rank_map = {p.code: i+1 for i,p in enumerate(sorted_by_v2)}
v3_rank_map = {p.code: i+1 for i,p in enumerate(sorted_by_v3)}
moves = sorted(pairs, key=lambda p: abs(v3_rank_map[p.code] - v2_rank_map[p.code]), reverse=True)[:10]
```

큰 순위 이동 (≥ ±10) 이 발생한 종목들이 V3 의 진짜 효과. 이번 사례:

| 종목 | V2 순위 | V3 순위 | Δ |
|------|---------|---------|---|
| SK하이닉스 | 21 | **5** | -16 (대형주 earnings_yield 보정으로 신규 진입) |
| 대한해운 | 22 | **9** | -13 (기술 0점이지만 펀더로 끌어올림) |
| 가온전선 | 10 | 20 | +10 (MA 가중치 감점으로 탈락) |
| DB하이텍 | 4 | 13 | +9 (MA + 펀더 안정성 동시 페널티) |

이런 reordering 이 V3 가 "단순 평행이동" 이 아닌 증거.

### 4. 컴포넌트별 평균 변화

```
| 컴포넌트 | V2 평균 | V3 평균 | 이론최대 V2 | 이론최대 V3 |
| 기술    | 18~23   | 12~14   | 40         | 50         |
| 펀더    | 12~16   | 7~9     | 40         | 30         |
| 리서치  | 8~10    | 7~9     | 20         | 20         |
```

이론최대 vs 실제 분포의 차이가 "의도와 결과의 괴리". 이번 사례에서 기술 점수의 이론 최대를 40 → 50 으로 올렸음에도 실제 최대는 25 → 20 으로 더 낮아짐 = ATR / 강양봉 / 거래량 sweet 조건이 KOSPI 거래량 상위 종목에서 동시 만족되기 어려운 임계 설정.

## 결론 도출 패턴

| ρ / 교집합 결과 | 해석 | 대응 |
|-----------------|------|------|
| ρ > 0.9, 교집합 ≥ 90% | 사실상 평행이동 | 컷오프만 조정, 알고리즘 변경 ROI 의심 |
| 0.7 < ρ < 0.9, 교집합 70~90% | **평행이동 + 가장자리 reordering** | 컷오프 조정 + 큰 이동 종목의 forward return 추적 (이번 사례) |
| 0.3 < ρ < 0.7 | 부분적 재정렬 | 컷오프 조정 + 컴포넌트별 IC 재검증 권장 |
| ρ < 0.3 | 거의 새 알고리즘 | forward test 필수, 컷오프 조정만으로 의사결정 금지 |

## 백테스트의 한계 — 두 알고리즘 비교에 부적합

V3 검증을 위해 백테스트를 돌리고 싶어지지만, 다음 이유로 거의 도움 안 됨:

1. **이중 점수 스케일**: 백테스트는 40점 만점 `_calc_buy_score(bars)` 만 사용, 라이브 screener 의 100점 (`screen_candidates()`) 과 별도. V3 변경은 100점 쪽이라 백테스트에 미반영
2. **펀더/리서치는 과거 시점 재현 불가**: 분기 데이터 (PER/ROE/EPS) 가 시점별 스냅샷으로 저장 안 됨. V3 변경의 절반 (`earnings_yield` 신규 / 안정성 4점 / EPS 절대값 폐기) 이 모두 펀더 영역
3. **수집 시점 스크리너 결과 미보존**: 매일 라이브 스크리너가 어떤 30종목을 뽑았는지의 스냅샷이 없으면 V2/V3 의 가상 매수 시뮬레이션 불가

→ 진짜 알파 비교는 **forward test** 외 방법 없음:

| 방법 | 가능? | 무엇을 알 수 있나 |
|------|-------|-------------------|
| run_backtest.py 그대로 | ✅ 즉시 | V2 vs V3 비교 불가 (40점 경로) |
| validate_score_ic.py 확장해 V2/V3 기술 점수만 IC 비교 | ✅ 1~2h | 기술 알파 변화는 보임. 펀더 효과 불가 |
| **Forward test**: 매일 점수 + N일 후 수익률 로깅 | ✅ 2~4주 | V3 전체 평가, 가장 신뢰 |
| 100점 스크리너 전체 과거 재현 | ❌ | (수집 스냅샷 부재) |

## 컷오프 임시 캘리브레이션 패턴

V3 분포에서 "과거 ≥62 통과 빈도 (6~21건/일)" 와 동등한 빈도를 회복하는 컷오프 계산:

1. V3 분포의 일별 점수 히스토그램 산출 (5/10~5/11 등 첫 며칠)
2. 일평균 5~10건 정도 통과하는 컷오프 찾기 → V3 에서는 ≥48
3. yaml 두 파일 (`config/strategies/scoring.yaml`: `buy_min_score_full`, `config/trading.yaml`: `min_score`) 모두 수정
4. 커밋 메시지에 명시: **"forward return 으로 검증된 컷오프가 아닌 임시 캘리브레이션. 2~4주 라이브 데이터 누적 후 V3 점수 vs 실제 수익률 평가 필요"**

## 일반 원칙

1. **알고리즘 교체 후 컷오프 미조정 = 매수 정지 사고** — 분포 평균이 바뀌면 그 자체로 컷오프 통과 빈도가 0 이 될 수 있음. 점수 변경 PR 에는 반드시 분포 시뮬레이션을 첨부
2. **Spearman ρ + Top-N 교집합** 두 지표가 비교의 핵심 — Pearson 만으로는 절대값 평행이동을 reordering 으로 오인 가능
3. **백테스트 ≠ 알고리즘 비교** — 백테스트가 작동하지 않는 점수 경로는 시작 전에 식별. forward test 인프라가 진짜 정답
4. **forward 로깅을 인프라로 구축** — 매일 매수 후보 + 점수 + entry price + N일 후 종가 를 단일 로그에 누적. 알고리즘 변경 의사결정의 표준 비교 자료
5. **컷오프 캘리브레이션은 임시 조치** — "분포 정상화" 만으로 끝내지 말 것. 정상화 후 forward return 으로 V3 가 V2 보다 진짜 나은지 검증

## 안티 패턴

- **점수 알고리즘 교체 후 매수 정지 → "잘못된 캘리브레이션이니 컷오프만 낮춤" 으로 종결** — V3 의 진짜 알파 효과를 검증 안 한 채 알고리즘만 갈아입힘. 컷오프 조정과 동등한지가 사실상 미확인
- **순위 비교 없이 컴포넌트 평균만 본다** — "기술 평균이 18 → 13 이 됐다" 만으로 "V3 가 더 보수적" 결론. 순위가 거의 같으면 의미 변화 없음
- **Pearson 만으로 비교** — 평행이동에 대한 분별력 없음. 반드시 Spearman 병행
- **단일 일자 비교** — 30 종목 × 1일 = 30 표본은 부족. 최소 며칠 누적

## V3 리버트 결정 — 모멘텀 전략과의 충돌 (2026-05-30)

V3 적용 3주 후, min_score=48 환경에서도 하루 종일 후보 0건이 발생. 단순 컷오프 문제가 아니라 **알고리즘 자체가 모멘텀 추종 전략과 충돌**한다는 결론.

### 충돌 포인트

| V3 변경 | IC 검증 데이터 | ht_trading 모멘텀 전략과의 충돌 |
|---------|----------------|----------------------------------|
| 신고가 역전: 돌파(100%+) 8점 → 직전(95~99%) 12점 | KOSPI 25종목 평균에서 직전 더 높음 | 모멘텀 추종은 돌파 종목을 선호 |
| 거래량 역전: 5배+ 감점 ("펌프 의심") | IC 기준 | 거래량 폭발 종목을 불이익 |
| MA 가중치 15→8 페이드 | IC 사실상 0 | 트렌드 추종에서 MA 정배열은 핵심 신호 |

**핵심 교훈**: IC 검증 데이터는 **KOSPI 평균 신호** 기준이다. 특정 스타일 전략(모멘텀, 가치, 역추세)은 평균 IC 와 반대 방향으로 작동할 수 있다. 전략 스타일과 신호 검증 집단(universe)이 일치하는지 확인이 필요.

### 선택적 재적용 — 전략 중립적인 개선만

V2로 완전 리버트 후, 전략 스타일에 무관한 두 가지만 재적용:

| 항목 | 내용 | 근거 |
|------|------|------|
| EPS → earnings_yield | EPS/Price × 100%로 교체. 고가주 절대값 보너스 버그 수정 | 전략 중립적 공정성 개선 |
| 캔들 세분화 | 강양봉(+2%) 5점 / 일반 양봉 3점 | IC +0.039로 전략 스타일 무관하게 실효 |

미적용: MA 페이드, 신고가 역전, 거래량 역전, ATR 신규 — 모두 모멘텀과 충돌하거나 모멘텀 전략에서 검증 미완료.

### 컷오프 복원

V3 기간(48) → V2 기준(62) 복원. 캔들 변경으로 일반 양봉 종목 최대 2점 낮아지는 효과만 있어 62가 적절.

## 재가중이 무효가 되는 조건 — 컷 근처 후보 풀이 얕을 때 (2026-07-04)

가중치 벡터를 바꿔도 결과가 안 변하는 **메커니즘**을 ht_dde 리웨이트 A/B 로 실측. 5개 가중치 변형(50/30/20 ~ 40/40/20)의 5일 수익률 중앙값이 거의 전부 -8.6% 로 동일했다.

- **이유**: 컷(62점) 근처 후보가 하루 2~3개뿐이고 상위 종목과 나머지의 격차가 10~20점 → 어떤 가중치 벡터로도 순위가 안 뒤집힌다 (예: 6/23 보해양조가 5개 변형 전부에 진입). "시험 반영비율을 바꿔도 전과목 1등은 어차피 합격"과 동형.
- **판정**: 후보 풀이 얇게 컷 근처에 몰려 있으면 재가중은 사실상 no-op — **가중치 실험을 종결하고 규칙(게이트) 실험으로 전환**하는 것이 옳다. Spearman ρ 를 재기 전에 "재정렬될 후보가 애초에 몇 개인가"부터 확인.

## A/B 실험 슬롯 운영 — 은퇴·재활용과 판정 기준 사전 등록 (2026-07-04)

페이퍼 트레이딩 변형들을 실험 슬롯으로 운영하는 방법론 (ht_dde 리웨이트에서 정립):

1. **결론난 실험은 은퇴** — 이력 보존 + 라이브 포지션 동결 후 슬롯을 새 가설로 재활용. 질문이 끝난 변형은 자리와 노이즈만 차지한다. (가중치 실험 4개 은퇴 → 규칙 실험 no_surge15/no_surge20/ma_ext30 으로 교체, 대조군 baseline 유지.)
2. **판정 기준 사전 등록(pre-registration)** — 변형마다 "표본 N픽 이상이면 벤치마크 대비 중앙값으로 판정" 식으로 결론 시점·기준을 미리 못박는다. 기준 없이 돌리면 "데이터 부족, 판단 불가"만 무한 반복.
3. **평균과 중앙값 병기** — 평균은 극단값 1개(-42% 종목 또는 상한가 1건)에 휘둘려 특정 변형이 우수해 보이는 착시를 만든다. 둘이 크게 벌어지면 "한두 종목이 결과를 지배 중"이라는 경고로 읽는다.
4. **필터 자체가 진단 도구** — no_surge15(급등픽 제외)가 3개 선정일에 뽑을 종목 0 → 그날 컷 통과 종목이 전부 급등픽이었다는 사실을 드러냄. 변형의 "무선정"도 데이터다.

## 데이터 원천 전환도 점수 버전 변경이다 (2026-09~10 사례)

Naver HTML 수집 중단 뒤 KIS 중심으로 바꾸며 기술/재무/리서치 비중 50/30/20은 유지했지만, 내부 리서치 배점·조회 기간·재무 입력이 달라졌다. 같은 총 비중은 같은 점수 분포를 보장하지 않는다. 기존 62점 컷의 후보 부족을 단순 비교 연산 버그로 판단하면 원인을 놓친다.

최종 기록에서는 KIS 시세·재무 수집을 유지하며 기존 조회수·리포트 수 점수식을 운영 DB에 복구했고 Naver 비교도 유지했다. 비교 기능 구현과 실제 소비 프로그램의 후보 선택 연결은 별도로 검증했다. 컷은 62로 유지하고 완결 forward 표본이 부족한 컷 비교를 확정 알파로 주장하지 않았다.

일자별 추천을 반복 관측한 백테스트는 같은 종목·같은 진입일을 여러 독립 거래로 세지 않도록 최신 관측 하나만 집계한다. 컷 통과 빈도 복원, 순위 변화, 비용 후 실현 성과는 서로 다른 판정이다.

## 컷 적용 전에 관측 중복을 제거한다

주말·휴일의 반복 관측이 같은 다음 거래일 진입으로 매핑되면 `(종목, 진입일)`별 최신 관측 한 건을 먼저 고르고, 그 뒤 컷과 게이트를 적용한다. 컷을 먼저 적용하면 최신 저점수 관측이 탈락한 뒤 오래된 고점수만 살아남아 실제 진입 시점의 판단을 왜곡한다. 과거 시점에 이용 가능했던 관측만 사용하며, 같은 종목의 반복 폴링을 독립 완결 거래로 세지 않는다.

10월 9일 수정으로 복구식 62점 컷의 완결 표본은 8건에서 7건으로 정정됐다. 이 검증은 다음 거래일 시가 진입·고정기간 청산 모델이며, 실제 장중 트레일링 체결 성과와 구분한다. 표본을 늘려 보이는 집계 오류를 먼저 고친 뒤 컷을 판단해야 한다.

## 후보 발굴·채점·매매 규칙의 효과를 분리한다

같은 후보 목록에 서로 다른 데이터 소스를 넣어 같은 식으로 채점하는 비교와, 서로 다른 소스가 발굴한 후보를 같은 데이터·식으로 채점하는 비교는 질문이 다르다. 후보 합집합을 쓸 때는 자본·보유 한도가 달라진 후보 수와 어떻게 상호작용하는지도 재현해야 한다.

10월 15일 세션 표본에서는 동일 후보에 KIS/Naver 데이터를 각각 적용해도 62점 통과 종목과 수익 결과가 같았다. 따라서 그 표본의 차이는 후보 발굴 범위에서 찾을 근거가 있으며, 이를 모든 기간의 소스 동등성으로 일반화하지 않는다. KIS 단독과 KIS+Naver 합집합 비교는 검증 과제이며 채택이 확정된 것은 아니다.

### 가격 진단과 전략 성과의 경계

- **고정기간 백테스트:** 관측 당시 점수·안전 필터로 고르고 다음 거래일 시가에 진입해 1일 또는 5일째 종가에 전량 청산하며 가정 비용을 차감한다. 추천 뒤 가격 움직임의 진단에는 쓰지만, 분할매수·고점 추적·손절·재진입을 반영한 전략 수익률로 해석하지 않는다.
- **실제 진입 고정 장중 재생:** 관측된 진입을 출발점으로 현재 청산 함수를 장중 기록에 적용해 추가매수·트레일링 조건의 영향을 본다. 실제 매수되지 않은 후보나 대체 진입, 현금 재배분을 재현하지 않으므로 전체 전략·추천 소스의 우열을 입증하지 않는다.
- **전체 전략 비교:** 같은 초기자본·비용·보유 한도·분할매수·청산 규칙에서 후보 소스 또는 컷만 바꾸고, 다음에는 선정 조건을 고정해 진입·청산을 비교한다. 과거 최적 조합은 별도 기간에서 재검증한다.

일봉의 고가·저가·종가만으로 매수 이후 고점과 스톱 도달 순서를 확정할 수 없다. 1분봉도 봉 안의 순서는 알 수 없으므로 근사 재생임을 명시하고, 장중 자료 부족·수집 누락과 체결 가정을 남긴다. 기존 저장 자료와 보완 가능한 과거 분봉을 먼저 확인하고, 재현할 수 없는 범위는 전방 페이퍼로 비교한다.

### 개선 폭보다 성과 집중도를 먼저 확인한다

변경별 총손익뿐 아니라 종목별 기여, 최대 기여 종목을 제외한 결과, 실현·미실현 손익을 함께 확인한다. 추가매수 중단이나 트레일링 확대가 한 손실·수익 종목 때문에 유리해 보일 수 있다. 제거 후 개선 방향이 뒤집히면 일괄 채택 근거가 약하며, 해당 상황의 진입·노출 조건을 더 좁혀 분석한다. 이는 인과 효과의 확정이 아니라 민감도 점검이다.

사례 수치와 다음 분석은 [[ht-trading-live-data-improvement-analysis]], 체결 시점 가정은 [[backtest-fill-model-adverse-selection]]을 참조한다.

## 수집 시작과 실제 사용 가능 시각을 구분한다

10/16 후속 구현에서 점수 이력에 수집 시작 시각만 있던 문제를 확인하고 완료 시각을 추가했다고 보고했다. 여러 종목을 수집·채점한 결과는 시작 시점부터 모두 알 수 있었던 정보가 아니다. 과거 재생은 저장 완료 이후부터 해당 실행의 점수를 사용하며, 사용 가능 시각을 입증하지 못한 자료는 추정해서 포함하지 않는다.

이번 세션은 최근 점수 실행 144개 모두에서 커밋 후 완료 로그를 찾았다고 보고했다. 이는 해당 구간의 재생 근거이며 과거 전체 이력의 시점 정확성을 보증하지 않는다. 이후 비교 페이퍼는 같은 실행의 KIS 점수·62점·매매 조건을 고정하고 후보 목록만 달리했다([[ht-dde]]).

### 종목 제외 검증에서는 현금도 다시 배분한다

전체 후보의 진입·분할매수·고점 추적·손절·재진입·현금 배분을 연결한 후속 재생에서 65점 컷이 유리해 보였다. 그러나 케이씨텍을 제외하고 현금 배분까지 다시 계산하면 KIS 단독의 65점 우위는 사라졌고, 합집합의 우위도 고점 반영 모형에 따라 뒤집혔다고 보고됐다.

이미 계산한 손익에서 한 종목의 기여만 빼는 점검과, 그 종목을 제외해 다른 후보의 매수·잔여 현금을 다시 계산하는 검증은 구분한다. 봉 내 고점 순서 가정까지 바꿨을 때 결론이 유지되는지 확인한다. 이번 결과는 운영 컷·소스 변경 근거로 채택하지 않았으며, 새 전방 비교와 함께 판단한다([[ht-trading-live-data-improvement-analysis]]).
